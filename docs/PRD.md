## 1. 版本變更摘要

V1.2 將 V1.1 的 LINE OA 入口改為完整網頁帳號與平台內互動，並加入學生學習功能。

| 項目 | V1.1 | V1.2 |
| --- | --- | --- |
| 學生入口 | LINE OA | 學生帳號登入網頁 |
| 身份 | LINE User ID | 平台帳號與固定角色 |
| 師生訊息 | LINE 與人工接管 | 站內一對一即時文字聊天 |
| 請假／調課 | LINE 申請、多方同意 | 網頁提出，以老師確認為生效條件 |
| 師生關係 | LINE 綁定碼 | 課程洽詢接受或邀請碼／連結 |
| AI 客服 | LINE＋首頁 | 首頁與登入後平台首頁 |
| 學習工具 | 無 | AI 鋼琴練習回饋、AI 測驗 |
| 長期推薦檔案 | 規劃中 | 不納入 MVP |

## 2. 產品願景

讓音樂老師在同一平台完成招生、課務、溝通與學習任務管理，也讓學生能找到適合課程、掌握上課安排，並獲得即時但不取代老師的 AI 練習輔助。

## 3. 問題陳述

### 3.1 老師

- 課程、學生、課表與訊息散落於多種工具。
- 請假與調課缺少一致的申請與確認紀錄。
- 出題、批改與回覆基礎練習問題耗時。
- 個人老師缺少兼具招生與課務管理的低成本平台。

### 3.2 學生

- 難以用自己的程度、目標、時間與預算找到適合課程。
- 課表、申請、訊息、教材與練習紀錄分散。
- 練習時無法即時知道節奏或錯音較集中的區段。
- 教材測驗缺少即時作答結果與錯題回饋。

## 4. 產品目標

1. 提供公開課程搜尋與自然語言課程推薦。
2. 提供老師與學生清楚分離的網頁工作區。
3. 將課程、學生、課表、請假／調課與訊息集中管理。
4. 以一對一即時聊天降低師生溝通斷裂。
5. 讓老師可由教材快速建立可審核、可自動批改的客觀題測驗。
6. 讓學生取得小節級、概略且可行動的鋼琴練習建議。

## 5. 非目標

- 不串接 LINE。
- 不做金流、電子發票、退款、分潤或正式會計。
- 不做同帳號多角色切換。
- 不做群組聊天、語音或視訊通話。
- 不讓 AI 未經老師審核直接發布測驗。
- 不讓 AI 自動核准請假或直接修改課表。
- 不將鋼琴回饋包裝為專業檢定、醫療或精密聲學量測。
- 不在 MVP 建立長期學生興趣／能力推薦檔案。

## 6. 角色

| 角色 | 說明 | 主要能力 |
| --- | --- | --- |
| 訪客 | 未登入使用者 | 瀏覽課程、AI 課程推薦、平台 QA、註冊、送出洽詢 |
| 學生 | 註冊時選擇學生角色 | 學生首頁、課表、申請、聊天、測驗、練習回饋 |
| 老師 | 註冊時選擇老師角色 | 老師後台、課程、學生、課表、聊天、教材、測驗、練習任務 |
| 平台管理員 | 平台維運角色 | 帳號、內容、異常、檔案與稽核管理 |

MVP 一個帳號只允許一個主要角色。角色變更或雙角色支援列入後續版本。

## 7. 核心使用情境

### 7.1 公開課程與 AI 客服

1. 訪客瀏覽分類課程或輸入自然語言需求。
2. AI 擷取課程類型、程度、目標、時間、地區、方式與預算。
3. 資訊不足且會影響結果時最多追問 2 題。
4. 後端從已上架課程建立候選並以規則排序。
5. 顯示推薦課程、理由與限制；訪客可送出洽詢。
6. AI 同時可回答平台功能與使用方式 QA。

### 7.2 師生關係建立

支援兩種方式：

- 課程洽詢：學生送出洽詢，老師接受後建立師生／修課關係。
- 老師邀請：老師建立限時邀請碼或連結，學生登入並確認後建立關係。

任何一方單獨輸入資料都不得直接建立正式關係；必須完成對方確認。

### 7.3 課表與異動

- 老師建立正式課堂與課表。
- 學生可提出請假或調課並留言。
- 老師可同意、拒絕或提出替代時段。
- 只有老師確認後，系統才能在交易中修改正式課表。
- 老師本人直接修改時，系統仍須二次確認並留下稽核紀錄。

### 7.4 站內聊天

- 具有有效師生關係的雙方可開啟一對一文字對話。
- 訊息即時顯示，保存聊天紀錄並計算未讀數。
- 使用者只能存取自己參與的對話。
- MVP 不支援聊天附件、群組、語音與視訊。

### 7.5 AI 測驗

1. 老師上傳教材。
2. AI 根據教材產生選擇題與是非題草稿，並附答案與解析依據。
3. 老師必須檢查、修改並明確發布。
4. 老師指派給學生；學生作答後系統自動批改。
5. 學生查看分數、答案與老師允許顯示的解析。

### 7.6 AI 鋼琴練習回饋

1. 老師建立練習任務並上傳樂譜圖片或參考音檔。
2. 學生在網頁授權麥克風並錄製演奏。
3. 系統分析參考資料與錄音，嘗試對齊小節或音樂區段。
4. 回饋採概略、鼓勵且可行動的語句，例如節奏稍慢、該小節錯音較集中。
5. 系統顯示辨識信心與限制；信心不足時不產生武斷結論，改請學生重錄或由老師查看。

## 9. 關鍵商業規則

| ID | 規則 |
| --- | --- |
| BR-01 | 註冊時角色固定為 teacher 或 student；MVP 不允許自行切換。 |
| BR-02 | 老師資料以 `studio_id` 隔離；後端不得相信前端傳入的角色或工作室。 |
| BR-03 | 課程推薦對談最多追問 2 題，結果只能來自有效資料庫課程。 |
| BR-04 | AI 課程推薦採「條件抽取 → 資料庫篩選 → 規則排序 → 產生說明」。 |
| BR-05 | MVP 不建立供未來自動推薦使用的長期學生興趣／程度檔案。 |
| BR-06 | 師生關係可由老師邀請或課程洽詢接受建立，兩者均需另一方確認。 |
| BR-07 | 學生提出請假／調課不會直接改變正式課表。 |
| BR-08 | 課務異動以老師確認為生效條件；拒絕、撤回、逾期或衝突均不得修改正式資料。 |
| BR-09 | 聊天限有效師生關係，且只能讀取自己參與的對話。 |
| BR-10 | 未讀數由伺服器端已讀位置計算，不信任前端自行傳入的未讀數。 |
| BR-11 | AI 生成測驗必須先是草稿；未經老師發布不得讓學生作答。 |
| BR-12 | MVP 測驗題型限單選題與是非題，由系統依老師核准答案自動批改。 |
| BR-13 | AI 鋼琴回饋為輔助建議，必須顯示信心與限制，不得宣稱精密診斷。 |
| BR-14 | 低信心鋼琴結果不應指稱特定音高誤差，應要求重錄或交由老師判讀。 |
| BR-15 | 檔案必須通過類型、大小、權限與安全檢查後才可供 AI 處理。 |

## 10. 驗收條件

| ID | 驗收條件 |
| --- | --- |
| AC-01 | 訪客可瀏覽、篩選並查看已上架課程。 |
| AC-02 | AI 能從需求產生結構化條件，最多追問 2 題，且不產生不存在的課程。 |
| AC-03 | 老師與學生註冊後進入不同頁面，學生無法存取老師 API。 |
| AC-04 | 課程洽詢經老師接受後可建立師生關係。 |
| AC-05 | 邀請碼／連結經學生確認後可建立師生關係，過期或撤銷邀請不可使用。 |
| AC-06 | 學生提交異動後正式課表不變；老師確認後才更新。 |
| AC-07 | 有效師生可即時傳送文字訊息、查看歷史與未讀數。 |
| AC-08 | 非對話成員無法讀取或發送該對話訊息。 |
| AC-09 | AI 產生的題目須經老師發布；學生完成後可正確自動計分。 |
| AC-10 | 瀏覽器可錄製鋼琴音訊並建立分析任務。 |
| AC-11 | 鋼琴結果可依小節／區段提供概略回饋並顯示信心；低信心不武斷判定。 |
| AC-12 | A 工作室老師無法讀取 B 工作室學生、教材、聊天或練習資料。 |

## 12. 主要風險與因應

| 風險 | 影響 | 因應 |
| --- | --- | --- |
| 樂譜圖片辨識錯誤 | 小節對齊與回饋錯誤 | 限制版面／曲目、顯示信心、保留老師覆核與重錄 |
| 參考音檔與學生速度不同 | 區段對齊失敗 | 採容忍速度差異的對齊、低信心降級為時間區段回饋 |
| 麥克風環境雜音 | 音高與節奏分析失真 | 錄音前檢測、環境提示、可重錄 |
| AI 出題脫離教材 | 學習內容不可信 | Retrieval 僅使用指定教材、附來源、老師審核後發布 |
| WebSocket 斷線 | 訊息未即時顯示 | 訊息先持久化、斷線重連、REST 補抓 |
| 跨租戶資料外洩 | 嚴重個資事件 | 後端 RBAC、`studio_id` 範圍、權限測試與稽核 |

## 13. 後續版本候選

- 同帳號多角色與角色切換。
- 長期學生興趣、程度與推薦個人化。
- 聊天附件、群組、語音或視訊。
- 主動通知 Email／Web Push。
- 更多測驗題型與老師自訂題庫。
- MIDI／MusicXML 輸入與更精準的音符級回饋。
- 線上付款、試上預約與正式報名。
