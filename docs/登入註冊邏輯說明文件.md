# 登入註冊邏輯說明

這份文件說明 **目前程式實際怎麼跑**，給組員對接老師端／學生端使用。  
不是產品規格書；規格仍以 PRD、SRS、功能製作與分工為準。

啟動方式：專案根目錄執行 `python3 app.py`，瀏覽器開 `http://127.0.0.1:8000`。

---

## 1. 一句話

使用者先選學生或老師 → 用 Email 密碼或 Google 建立帳號 → 登入後 Session 記住 `user_id` → 依 `role` 與老師申請狀態進入對應頁面。

| 身份 | 註冊後 | 登入後去哪 |
| --- | --- | --- |
| 學生 | `role=student`，立刻可用 | `/student` |
| 老師 | `role=teacher`，申請 `pending`，`is_active=False` | `/teacher`（等待審核） |
| 老師（已核准） | 申請 `approved`，`is_active=True` | `/teacher`（老師頁） |
| 老師（已駁回） | 申請 `rejected`，不能用老師功能 | `/teacher`（未通過頁） |
| 管理員 | `.env` 的 `ADMIN_EMAIL` 啟動時建立 | `/admin/teacher-applications` |

管理員核准後才把老師 `is_active` 設成 True，並維持 `role=teacher`。

---

## 2. 請求怎麼往下走

```text
瀏覽器（templates/*.html）
    → app.py（掛 Session、載入 router）
        → routers/auth.py 或 routers/admin.py（路由）
            → services/（規則：註冊、登入、審核、Google）
                → repositories/（查詢／寫入）
                    → models/（users、teacher_applications、auth_identities）
                        → PostgreSQL
```

密碼不會明文進資料庫。`backend/core/security.py` 用 Argon2 做成 `password_hash`。  
登入成功後只把 `user_id` 放進 Cookie Session，之後每頁用 `get_session_user()` 找回使用者。

JSON API（給之後前端）走同一套 Service，路徑在 `/api/auth/...`。

## 3. 網頁流程

### 學生註冊

```text
GET  /register              選「我是學生」
GET  /register/student      Email、密碼、基本資料
POST /register/student      建立學生 → 導向 /login?registered=student
POST /login                 Session 寫入 user_id → /student
```

表單下方「使用 Google 帳號註冊」會到 `GET /auth/google?role=student`。

### 老師註冊（Email）

```text
GET  /register              選「我是老師」
GET  /register/teacher      基本資料 + 教學項目／經歷／簡介（證明文件選填）
POST /register/teacher      建立老師 + pending 申請 → /login?registered=teacher
POST /login                 → /teacher（等待審核）
管理員核准後                is_active=True → 可進老師功能
```

### 老師註冊（Google）

```text
GET  /auth/google?role=teacher
GET  /auth/google/callback     建立 Google 老師帳號（尚未核准）
GET  /register/teacher/application   補填申請資料
POST /register/teacher/application   狀態 pending → /teacher
```

### 登入／登出／基本資料

```text
GET  /login
POST /login                 Email 密碼；失敗不寫 Session
POST /logout                清除 Session → /
GET  /profile 、 POST /profile
```

登入頁下方「使用 Google 帳號登入」是 `GET /auth/google?intent=login`。  
還沒註冊過的 Google 帳號不能從登入頁直接建號，要先走註冊並選身份。

### 管理員審核老師

```text
GET  /admin/teacher-applications
POST /admin/teacher-applications/{id}/approve
POST /admin/teacher-applications/{id}/reject
GET  /admin/teacher-applications/{id}/proof    有上傳才下載
```

本機測試管理員：`.env` 設 `ADMIN_EMAIL`、`ADMIN_PASSWORD`，啟動時自動建立（不要把 `.env` 推上 Git）。

## 4. 路由一覽

程式在 `backend/routers/auth.py` 與 `backend/routers/admin.py`，由 `app.py` 掛上。

### 網頁

| 方法 | 路徑 | 做什麼 |
| --- | --- | --- |
| GET | `/` | 測試首頁 |
| GET | `/register` | 選學生或老師 |
| GET | `/register/student` | 學生註冊表單 |
| POST | `/register/student` | 建立學生 |
| GET | `/register/teacher` | 老師註冊表單 |
| POST | `/register/teacher` | 建立老師與 pending 申請 |
| GET／POST | `/register/teacher/application` | Google 老師補申請 |
| GET | `/auth/google` | 開始 Google；`role=student\|teacher` 或 `intent=login` |
| GET | `/auth/google/callback` | Google 回來後登入或註冊 |
| GET／POST | `/login` | 登入表單／驗證密碼 |
| POST | `/logout` | 登出 |
| GET／POST | `/profile` | 基本資料 |
| GET | `/student` | 學生頁；未登入去 `/login` |
| GET | `/teacher` | 依申請狀態顯示等待／駁回／老師頁 |
| GET | `/admin/teacher-applications` | 申請列表（僅 admin） |
| POST | `/admin/teacher-applications/{id}/approve` | 核准 |
| POST | `/admin/teacher-applications/{id}/reject` | 駁回 |
| GET | `/admin/teacher-applications/{id}/proof` | 下載證明文件 |

### JSON（同一套帳號）

| 方法 | 路徑 | 做什麼 |
| --- | --- | --- |
| POST | `/api/auth/register` | 只建立 **學生** |
| POST | `/api/auth/login` | 登入並寫 Session |
| POST | `/api/auth/logout` | 登出 |
| GET | `/api/auth/me` | 目前登入者；未登入 401 |

老師 JSON 註冊尚未提供，測試請用網頁表單。

權限輔助函式在 `backend/dependencies.py`：

- `get_session_user`：Cookie 有 `user_id` 才查出人
- `get_current_user`：沒登入就 401（JSON 用）
- `require_roles("teacher")`：要已啟用且角色符合

老師功能以 `is_active=True` 且申請 `approved` 為準。網頁路由目前多用 Session 再自己判斷，還沒全部改成 `require_roles`。

## 5. 資料表

Alembic 檔案在 `alembic/versions/`。本機空資料庫請執行：

```bash
alembic upgrade head
```

| 表 | 用途 |
| --- | --- |
| `users` | Email、密碼雜湊、姓名、電話、生日、性別、`role`、`is_active`、`auth_provider` |
| `teacher_applications` | 教學項目、經歷、簡介、選填證明文件、`pending`／`approved`／`rejected` |
| `auth_identities` | Google 的 `provider` + `provider_subject`，對應 `users.id` |

`role` 只能是 `student`、`teacher`、`admin`。公開註冊不能當 admin。  
Google-only 帳號的 `password_hash` 可為空，不能用 Email 密碼登入。

證明文件若有上傳，存在專案 `uploads/teacher_proofs/`（已 gitignore）。

規格書裡的 `teacher_profiles`、`student_profiles` 還沒建；老師申請先用 `teacher_applications`。

## 6. 用到的工具與套件

| 用途 | 工具 | 程式位置 |
| --- | --- | --- |
| 網站與 API | FastAPI、Uvicorn | `app.py` |
| 網頁模板 | Jinja2 | `templates/` |
| 記住登入 | Starlette `SessionMiddleware`、`itsdangerous` | `app.py` |
| 表單與上傳 | `python-multipart` | 註冊 POST |
| 檢查 Email 格式 | `email-validator`、Pydantic `EmailStr` | `auth.py`、`schemas/user.py` |
| 密碼雜湊 | `argon2-cffi` | `backend/core/security.py` |
| ORM／資料庫 | SQLAlchemy 2、`psycopg`、PostgreSQL 16 | `backend/core/database.py` |
| 建表 | Alembic | `alembic/` |
| Google 驗證 | 標準庫 `urllib` 呼叫 Google OAuth | `backend/services/google_auth.py` |

`.env`（不要提交 Git）常用變數：

| 變數 | 用途 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 連線，例如 `postgresql+psycopg://aipe04:aipe04@localhost:5432/aipe04` |
| `SESSION_SECRET_KEY` | 簽署 Session Cookie |
| `ADMIN_EMAIL`、`ADMIN_PASSWORD` | 本機測試管理員 |
| `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GOOGLE_REDIRECT_URI` | Google 登入；未設定會顯示說明頁 |

Google Redirect URI 請設：`http://127.0.0.1:8000/auth/google/callback`

本機 PostgreSQL 可用專案根目錄：

```bash
docker compose up -d postgres
```

## 7. 對接時請這樣判斷身份

1. 用 Session 或 `GET /api/auth/me` 取得使用者。
2. `role == "student"` 且 `is_active == true` → 學生工作區。
3. `role == "teacher"` 且 `is_active == true` → 老師工作區。
4. `role == "teacher"` 且 `is_active == false` → 只顯示等待／駁回，不要開放課程、學生、作業。
5. 不要讓前端自己改 `role`；後端以資料庫為準。
