# 共用本機 AI 找課設計草案

## 目標與限制
組員開啟 Render 測試站即可使用運行於 Ollie Mac 的 Qwen 與 BGE-M3；沿用 Vue、FastAPI、Supabase 正式 courses。Mac 需開機、登入、網路可用；不宣稱全天候正式服務。最多兩次系統追問；僅已發布鋼琴課；不得由練習分數推定找課程度；不可洩漏學生錄音、密碼與金鑰。

## 方案
A. 各自安裝模型：互不依賴，但組員需設定環境。B. Mac 模型經安全通道供 Render 後端使用：符合使用者選擇，推薦本方案。C. 外部付費 API：可免 Mac 常駐，但本輪不使用。

## 架構
瀏覽器→Render FastAPI→具身分驗證與限流的私人 HTTPS 通道→Mac 僅限 localhost 監聽的受限模型閘道→Ollama（Qwen3 4B Instruct 與 BGE-M3）。不得將無驗證 Ollama 原始 API 對網路公開。通道方案以能安全保護機器對機器憑證、可取得穩定網址為準；Cloudflare quick tunnel 僅供臨時驗證，需另行評估 Cloudflare account/domain 與可用額度。Render 組態不放前端或 Git。

## 應用功能
從 feature/AICourseFinder 研究原型選擇性移植，而非整支分支覆蓋：結構化需求、狀態增量與修正、動態最多兩次追問、必要條件硬篩選、語意排序及可核對來源。復用正式 courses，不建第二套帳號或課程真相。資料不夠時標記未知；未經使用者同意不放寬硬條件。沿用現在對話 ownership；新增修改與重新查詢的正式 API/介面，保護既有客戶端。Qwen 模型與索引版本可配置；模型離線時明確告知並維持一般搜尋。

## 漸進交付
1. 盤點原型、正式程式、主線差異及備份；建立隔離測試庫與本機需求理解／檢索基準。
2. 移植對話理解及狀態，測試否定、多輪修正、追問上限、身份隔離與失敗恢復。
3. 建立 BGE-M3 語意檢索，合併必要條件與文字搜尋；索引依課程版本重建，僅供已發布資料；本機／雲端隔離遷移。
4. 在相同候選資料比較直接生成與 Refine 多次迭代；不得跨課程混用證據，驗證引用與欄位；記錄準確度、呼叫數、延遲及順序影響，依實測決定預設。
5. 建立本機受限閘道與安全隧道，測驗無憑證拒絕、併發上限、超時、Mac 離線、恢復；Render 僅設定後端秘密。
6. 端到端驗證、記錄操作和限制，審核結果後部署；Render 現為手動部署，不假設合併 main 即部署。正式知識文件 RAG 使用獨立已核准、帶版本與來源的資料集合。

## 驗證與風險
沿用既有原型題庫並新增未用於提示詞調整的繁中口語、多輪否定、更正、無結果及來源事實性案例；同一候選集盲評直接生成與 Refine，統計正確率、p50/p95、記憶體與多使用者負載。執行單元、整合、權限、migration、瀏覽器與實際遠端回路測試。調查現有備份告警並恢復備份或確保驗證過的備份後，才對共享庫執行 migration。未滿足資料備份或模型容量條件時不聲稱穩定上線。
