# AICourse 全端整合設計

## 目的

把 `feature/AICourseFinder` 已驗證的對話式找課體驗搬進目前正式產品。訪客在首頁用自己的話描述想學的鋼琴內容；系統最多追問兩次，之後只從正式資料庫的已發布課程中推薦，並說明哪些條件相符、哪些課程資料仍未知。

## 成功條件

- 正式 FastAPI 提供 `/api/recommendations`、`/{session_id}/answer`、`/{session_id}`。
- 訪客不必登入；同一筆對談只能由建立它的瀏覽器讀取或回答。
- 一次對談最多追問兩題，未提供的找課條件維持 `null`。
- 只推薦 `courses.status = 'published'` 的課程；沒有符合課程時回傳空陣列，不產生假課程。
- 找課程度只來自訪客本次對談，練習分數不參與。
- Vue 右下角既有「AI 找課」面板可完成輸入、追問、結果顯示與前往洽詢。
- 沒有 Gemini 金鑰或模型失敗時，規則式找課仍可運作。

## 架構決定

### 沿用正式資料

課程唯一來源是既有 `courses` 與 `users`。不搬入舊分支的 `ai_public_courses`、示範老師或第二套登入。這可保證推薦卡上的課程一定是老師在正式後台發布的課程。

### 保存對談與結果

Alembic 011 新增：

- `recommendation_sessions`：保存瀏覽器擁有者、訪客訊息、整理後條件、已問題數、狀態與到期時間。
- `recommendation_items`：保存這次回傳的課程順序、符合條件、未知欄位與推薦理由；`course_id` 外鍵指向正式 `courses`。

瀏覽器擁有者放在既有簽章 Session Cookie，資料庫只保存隨機識別值的 SHA-256，不保存 Cookie 本身。

### 條件理解

第一版把舊 AICourse 已驗證的明確說法解析規則搬入正式服務，包括找課程度、曲風、線上或實體、地區、預算及時段。只接受使用者明確說出的內容；問句、否定或模糊內容不擅自確認。

系統優先追問找課程度，其次追問上課方式。回答「不知道／都可以」會留下未知，不反覆追問同一題。兩題用完後直接依已知條件搜尋。

### 推薦規則

- 已知條件必須由課程資料明確符合；課程該欄位為空時不算符合。
- 使用者未提供的條件不作為篩選條件。
- 結果依符合條件數、建立時間及課程 ID 穩定排序，最多三門。
- 推薦理由由伺服器根據實際命中欄位組合，不讓模型編寫課程事實。

### 前端體驗

沿用目前 Vue 的暖色首頁和右下角入口。面板包含：

- 對話紀錄與最多兩次追問。
- 送出中、錯誤、無結果狀態。
- 找課條件摘要。
- 最多三張推薦卡；每張卡可前往既有 `/courses/:id/contact` 洽詢流程。
- 「重新開始」清除目前畫面並建立新對談。

## 不在本次範圍

- 舊 Next.js 網站與其 Playwright 測試。
- `ai_public_courses`、示範課程及獨立 Alembic。
- 公開問答 RAG、向量索引、課程 embedding、互動分析報表。
- 依練習分數推測學生程度。
- 自動建立接洽對話；訪客仍經既有登入／註冊與洽詢流程。

## 合併順序

本分支包含正式 Vue、最新後端和資料庫 010，AICourse Migration 接成 011。PR 會標明依賴資料庫 PR #29；資料庫及全端基礎進入共同目標後，AICourse 變更即可維持單一 Alembic 路線合併。
