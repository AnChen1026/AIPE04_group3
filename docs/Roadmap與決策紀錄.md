# 個人工作室智慧管理平台 Roadmap 與決策紀錄

| 項目 | 內容 |
| --- | --- |
| 版本 | V1.2 |
| 最後更新 | 2026-09-24 |

## 1. 建議開發順序

### Phase 0：規格與骨架

- 對齊 V1.2 文件與現有 Repository。
- 確認 Auth、Object Storage、Background Job 與 WebSocket 技術。
- 建立共用錯誤格式、權限 Dependency、Database Session 與測試基礎。

### Phase 1：核心帳號與課務

- 老師／學生註冊、登入與固定角色。
- 工作室、課程、學生、洽詢與邀請。
- 師生關係、課表與老師確認式異動。

### Phase 2：站內聊天

- 對話與參與者資料表。
- 歷史訊息、未讀數、REST 備援。
- WebSocket 即時收送、重連與權限測試。

### Phase 3：首頁 AI 與課程推薦

- 平台 QA 知識來源。
- 條件與程度抽取。
- Database Filter、規則排序與推薦理由。
- 訪客洽詢串接。

### Phase 4：AI 測驗

- 教材上傳、驗證與文字擷取。
- 題目草稿、老師審核與發布。
- 指派、作答、自動批改與版本。

### Phase 5：鋼琴回饋 Prototype

- 固定測試曲目與標註資料。
- 麥克風錄音、上傳與品質檢查。
- 樂譜圖片／參考音檔處理與區段對齊。
- 小節級回饋與低信心降級。

### Phase 6：整合與 Demo

- E2E、權限、資安與效能測試。
- Demo 測試資料與失敗備案。
- 文件、部署與操作說明同步。

## 2. 已確認決策

| ID | 決策 | 理由／影響 |
| --- | --- | --- |
| D-01 | V1.2 不串接 LINE | 身份、通知與訊息全部移至網頁平台 |
| D-02 | 註冊時選老師或學生，MVP 單一固定角色 | 降低權限與頁面複雜度 |
| D-03 | 老師與學生都有專屬頁面 | 分離操作與授權範圍 |
| D-04 | 首頁保留課程推薦、平台 QA 與程度辨識 | 維持招生／媒合入口 |
| D-05 | 登入學生的長期推薦 Profile 不納入 MVP | 控制範圍與個資風險 |
| D-06 | 師生關係同時支援洽詢接受與老師邀請 | 支援平台招生與既有學生匯入 |
| D-07 | 課務異動以老師確認為生效條件 | 老師保留最終課表控制權 |
| D-08 | 站內聊天為即時一對一純文字 | MVP 提供核心溝通、控制複雜度 |
| D-09 | AI 測驗限選擇／是非題，老師審核後發布 | 可確定性自動批改並降低幻覺風險 |
| D-10 | 鋼琴輸入使用瀏覽器麥克風 | 學生不用額外設備 |
| D-11 | 老師可提供樂譜圖片或參考音檔 | 符合實際教學素材 |
| D-12 | 鋼琴回饋需小節級但採概略語句 | 保留教學價值，不假裝精密診斷 |
| D-13 | 低信心鋼琴結果必須降級 | 防止錯誤回饋傷害信任 |

## 4. 風險 Gate

### Gate A：核心平台

未完成 Auth、RBAC、租戶隔離與正式師生關係前，不開始讓 AI 存取學生資源。

### Gate B：聊天

未通過 participant 權限、訊息去重與斷線補抓，不宣告聊天完成。

### Gate C：測驗

未完成老師審核與版本控制，不開放學生作答。

### Gate D：鋼琴回饋

固定測試曲目的小節／區段對齊與低信心降級未通過前，不將功能描述為可支援任意樂譜與曲目。

## 5. 文件變更規則

- 產品範圍或商業規則：更新 PRD。
- 可驗收系統行為：更新 SRS。
- 操作步驟或狀態：更新 User Flow。
- 元件、部署或責任邊界：更新 SAD。
- Endpoint／Schema：更新 API。
- Table／Constraint／Migration：更新 Data。
- AI 輸入、輸出、門檻或降級：更新 AI 功能規格。
- 決策定案後，將 O-xx 移至 D-xx 並記錄日期。
