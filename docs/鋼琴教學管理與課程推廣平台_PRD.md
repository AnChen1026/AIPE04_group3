# 鋼琴教學管理與課程推廣平台 PRD

| 項目 | 內容 |
| --- | --- |
| 版本／日期 | V1.2／2026-09-30 |
| 階段 | MVP；產品方向已確認，工程參數待驗證 |
| 主要對象 | 鋼琴老師及鋼琴學生 |
| 使用入口 | 網站首頁、老師工作區、學生工作區 |

## 1. 專題方向

建立一個整合鋼琴課程推廣、教學管理及 AI 學習輔助的網站平台。訪客透過首頁智能推薦與程度辨識找到合適的鋼琴課；學生登入後錄製練習，取得快速回饋；老師在課前取得有依據的學生練習摘要，安排教學重點。

## 2. V1.2 決策與變更

| 項目 | 舊方向 | V1.2 已確認方向 |
| --- | --- | --- |
| 產品範圍 | 個人工作室管理、多樂器媒合 | 鋼琴教學管理與課程推廣 |
| 師生入口 | V1.1 學生使用 LINE | 師生都在網站內，移除 LINE 功能 |
| 推廣 | 多樂器、跨工作室及訂閱推廣 | 公開鋼琴課程、程度辨識、智能推薦 |
| 推薦後續 | LINE 或外部聯絡 | 註冊學生後站內洽詢 |
| 練習回饋 | 輸入及時效尚未定案 | 錄完送出後快速回饋；必要參考答案為 MIDI |
| 演奏驗收 | 曾討論完整雙手／踏板 | 先限短曲、單音或簡單雙手、無踏板 |
| 老師課前資訊 | 查看個別練習 | 彙整上次課後至本次課前的練習，產生自然語言摘要 |
| AI 測驗 | 曾討論是否限縮 | 保留教材出題、老師審核及學生作答 |

本輪確認：摘要由老師開啟課堂頁時產生／更新；不要求固定課前排程。「即時」在本版指錄完後快速處理，不包含邊彈邊提示。

## 3. 使用者問題與產品目標

- 老師需要集中管理學生、課表、申請、教材與練習，降低課前逐筆查閱時間。
- 學生需要在課後知道哪裡練得好、哪個小節需改善，並保存歷次紀錄。
- 找課者需要描述目標與經驗，取得適合程度、時段、方式及預算的真實課程。

產品目標是建立「找課 → 洽詢 → 建立師生關係 → 上課與練習 → 回饋 → 課前摘要」的完整流程。

## 4. 角色與權限

| 角色 | 能做的事 |
| --- | --- |
| 訪客 | 看公開鋼琴課程、使用推薦與程度辨識、查看詳情；洽詢前註冊 |
| 學生 | 洽詢、申請加入老師、個人課表、課務申請、聊天、練習與測驗 |
| 老師 | 公開課程管理、回覆洽詢、師生關係確認、學生／課表管理、作業、教材、測驗、課前摘要 |
| 平台維運管理員 | 必要帳號／異常處理與稽核；完整管理員介面延後 |

註冊帳號維持單一老師或學生角色。既有工作室資料隔離保留，不因聚焦音樂老師而把不同老師的資料混合。

## 5. MVP 功能

| ID | 功能 | MVP 行為 |
| --- | --- | --- |
| F01 | 公開鋼琴課程 | 展示、搜尋／篩選、詳情，老師可發布／封存 |
| F02 | 智能推薦與程度辨識 | 描述需求 → 結構化條件 → 初步程度 → DB 篩選排序 → 推薦理由 |
| F03 | 網站登入 | 註冊、登入、登出、基本資料及角色分流 |
| F04 | 洽詢與師生關係 | 登入後洽詢；雙向同意才建立正式關係與修課 |
| F05 | 教學管理 | 學生清單、課表、約課／請假／調課申請，老師確認後生效 |
| F06 | 站內聊天 | 有效師生一對一即時文字、未讀數及歷史 |
| F07 | 鋼琴練習回饋 | 老師發 MIDI 作業；學生錄音；分析音高／節奏及差異；LLM 回饋 |
| F08 | 老師課前練習摘要 | 依本次課堂彙整上次課後練習，提供進步、反覆問題與教學建議 |
| F09 | 教材與 AI 測驗 | 上傳教材、AI 草稿、老師審核發布、學生作答、後端批改 |
| F10 | 基礎維運 | 權限、受保護檔案、處理狀態、重試、稽核及備份 |

平台問答可沿用既有首頁客服的基本說明；不要求新增大型知識庫或將客服改為自主改課 Agent。

## 6. AI 與後端的分工

| 應用 | AI／模型負責 | 後端負責 |
| --- | --- | --- |
| 推荐與程度 | 理解學習目標、整理證據、必要追問與推薦說明 | 驗證條件、程度規則、真實課程篩選與排序 |
| 練習辨識 | 音訊轉音符事件 | 與參考 MIDI 對齊、計算差異與分數 |
| 學生回饋 | 將結構化差異說成學生理解的文字 | 提供可信結果與版本，不讓 LLM 自行定分 |
| 老師課前摘要 | 將統計與差異整理成教學摘要 | 確定時間窗口、授權範圍、有效來源及是否需更新 |
| AI 測驗 | 根據教材產生題目草稿 | 格式驗證、審核發布、標準答案批改 |

第一版使用現有模型能力，不訓練自有音訊模型。具體套件與模型延續現有專案，沒有在本輪擅自更換。

## 7. 關鍵規則

1. 僅提供鋼琴課程；樂器欄位固定 piano，風格可有古典、流行等。
2. 程度採入門、初階、中階、進階、不確定；僅為推薦推估，不是檢定。
3. 每次推薦對談最多追問兩題；未知資訊標記未知，不臆造。
4. 推薦只能來自有效工作室的已發布、可洽詢鋼琴課程。無符合項目時先說明，再讓使用者選擇放寬條件。
5. 不採訂閱付費優先排序；本版不要求原工作室優先或外部推廣資格邏輯。
6. 洽詢不等於報名，不自動取得老師私訊／教材／練習資料；雙向同意後才有正式師生權限。
7. 課務申請須老師確認；權限與時間衝突檢查通過後在交易中執行。
8. 練習作業必要參考為經校驗 MIDI；樂譜／音檔可作輔助，圖片或音檔轉答案延後。
9. 錄音為短曲、單音或簡單雙手、無踏板的 MVP 驗收範圍；複雜演奏不宣稱已支援。
10. 音高與節奏分開判斷；辨識低信心或資料不足時保守回饋，失敗不代表 0 分。
11. 課前摘要只使用該學生、該老師、該修課關係的資料；可引用該修課內多份作業。
12. 公開課程頁不能顯示個別學生錄音、成績或課前摘要。

## 8. 課前摘要精確定義

本次課堂必須存在且學生有參與關係。時間窗口從同一修課關係在本堂之前最近一堂已完成課的 ends_at 起，至 min(老師查看時間, 本次課 starts_at)；採 [起點, 終點)，避免重複計入。

第一次上課無前堂時，建議從修課 started_at 起算；若缺少該日期則明示使用建立修課時間。這是工程邊界建議，並非已完成實作。

摘要呈現：期間、平台提交次數／日期、完成與失敗數、最近有效表現、可比對的變化、反覆錯誤及下堂教學建議。未完成分析不當成練不好，沒有紀錄顯示「此期間沒有平台練習紀錄」，不能說「學生沒有練習」。

僅同作業、同參考與可比較評分設定可做分數趨勢；不同曲目不能直接推論進步／退步。列出生成時間、來源提交及處理中項目；有新結果或課堂改期時標記摘要需要更新，老師可重新產生。

## 9. MVP 不包含

LINE OA／Webhook／Push、其他樂器、邊彈邊回饋、複雜雙手與踏板的全面驗收、樂譜／音檔自動轉參考答案、自有模型訓練、金流與扣堂、訂閱競價推廣、即時自動預約、正式能力檢定及登入後長期偏好推薦。

## 10. 驗收與待定參數

| 驗收 | 判準 |
| --- | --- |
| 推薦 | 不生成不存在的課程；最多追問兩題；符合條件及不確定處清楚呈現 |
| 權限 | 改學生／老師／課程／檔案 ID 不能越權 |
| 練習 | 固定短曲測試可辨識已知錯音／漏音／節奏差異；結果可追溯參考及版本 |
| 快速回饋 | 顯示待處理、處理中、完成／失敗；在實際部署測得延遲後定數值目標 |
| 課前摘要 | 正確時間窗口、只引用有效来源；無紀錄與分析失敗正確表達 |
| 測驗 | 草稿需審核；交卷前答案不外洩；重複交卷不重複批改 |

負責人已於 2026-10-05 更新。第一版提供 Google 登入，登入狀態使用 HttpOnly Cookie Session，網站使用 Next.js。

仍待定：教材格式、錄音最大長度、評分容許誤差、延遲目標、申請時限及測驗重考規則。這些不改變已定方向。
