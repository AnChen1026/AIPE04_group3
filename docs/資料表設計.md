# 鋼琴教學管理與課程推廣平台－目前資料表

| 項目 | 內容 |
| --- | --- |
| 版本／日期 | V1.4／2026-10-15 |
| 依據 | 目前 Models 與 Alembic `001`～`005` |
| 產品規則 | PRD、SRS、User Flow V1.4 |

這份文件描述現在專案實際使用的資料表。舊版 V1.2 的 30 張表草案不再作為建表依據。

正式表由 Alembic 建立。`teacher_profiles` 目前由 `app.py` 啟動時的 `Base.metadata.create_all()` 補建，之後應補成正式 Migration。

老師與學生共用 `courses`。學生的接洽、綁定、課表、課務申請和練習也使用下面同一組表。每筆學習資料都要能辨識所屬老師與課程，不能只靠學生查詢。

## 1. 正式資料表

| 資料表 | 用途 | 建立方式 |
| --- | --- | --- |
| `users` | 老師、學生、管理員帳號 | Alembic `001`、`002` |
| `teacher_applications` | 老師申請與審核 | Alembic `002`、`003` |
| `auth_identities` | Google 登入身份 | Alembic `002` |
| `teacher_profiles` | 老師頁使用的老師資料 | 啟動時補建 |
| `courses` | 鋼琴課程 | Alembic `004` |
| `inquiry_conversations` | 一位學生對一門課的接洽對話 | Alembic `004` |
| `conversation_messages` | 接洽對話訊息 | Alembic `004`、`006` |
| `course_bindings` | 學生與課程的綁定 | Alembic `004` |
| `binding_codes` | 只給一位學生、一門課的綁定碼 | Alembic `004` |
| `lesson_sessions` | 正式課表 | Alembic `004` |
| `change_requests` | 約課、請假、調課 | Alembic `004` |
| `practice_recordings` | 練習錄音 | Alembic `004` |
| `practice_feedbacks` | 一筆錄音的音高、節奏與文字 | Alembic `004` |

Alembic `005_unify_courses` 會把舊的 `teacher_module_courses` 搬進 `courses`，搬完後刪除舊表。

## 2. 帳號

### 2.1 users

| 欄位 | 說明 |
| --- | --- |
| `id` | UUID 主鍵 |
| `email` | 唯一 |
| `password_hash` | 密碼雜湊。Google-only 帳號可空 |
| `name` | 姓名 |
| `phone_number` | 電話，可空 |
| `birthdate` | 生日，可空 |
| `sex` | 性別，可空 |
| `role` | `teacher`、`student`、`admin` |
| `is_active` | 帳號是否可用。老師核准後才為 true |
| `auth_provider` | `password` 或 `google` |
| `created_at` | 建立時間 |

### 2.2 teacher_applications

一位老師最多一筆申請。狀態為 `pending`、`approved`、`rejected`。證明文件可空，檔案放在 `uploads/teacher_proofs/`，資料庫只存路徑與檔名。

主要欄位：`user_id`、`teaching_subjects`、`teaching_experience`、`bio`、`proof_file_path`、`proof_file_name`、`status`、`review_note`、`reviewed_at`、`reviewed_by`。

### 2.3 auth_identities

保存 Google 的 `provider` 與 `provider_subject`，並連回 `users.id`。

### 2.4 teacher_profiles

`user_id` 連回 `users.id`，一位使用者一筆。老師 API 用這張表確認老師身份。學生流程的 `teacher_id` 仍使用 `users.id`，不是這張表的 `id`。

## 3. 課程、接洽與綁定

### 3.1 courses

| 欄位 | 說明 |
| --- | --- |
| `id` | UUID 主鍵 |
| `teacher_id` | 授課老師，FK → `users.id` |
| `title` | 課程名稱 |
| `level` | 找課程度，可空 |
| `style` | 風格，可空 |
| `delivery_mode` | 線上或實體，可空 |
| `region` | 地區，可空 |
| `price_per_lesson` | 單堂價格，可空 |
| `time_slots` | 可洽詢時段，可空 |
| `status` | `draft`、`published`、`archived` |
| `reference_midi_path` | 這門課的一份參考 MIDI，可空 |
| `created_at` | 建立時間 |

只有 `published` 可以被學生洽詢。

### 3.2 inquiry_conversations

一位學生對一門課只有一段對話。綁定前後使用同一段。

唯一條件：`student_id` + `course_id`。同時保存 `teacher_id`。

### 3.3 conversation_messages

| 欄位 | 說明 |
| --- | --- |
| `conversation_id` | FK → `inquiry_conversations.id` |
| `sender_id` | 發訊者，FK → `users.id` |
| `client_message_id` | 瀏覽器產生的訊息編號，可空。同一段對話不可重複，用來避免 WebSocket 重送變成兩筆 |
| `body` | 訊息內容 |
| `created_at` | 送出時間 |
| `read_at` | 對方已讀時間，可空 |

### 3.4 course_bindings

學生和一門課的上課資格。狀態為 `bound` 或 `unbound`。解除綁定只關閉該課的教學功能，不刪除接洽對話。

唯一條件：`student_id` + `course_id`。

### 3.5 binding_codes

`code` 唯一。一組碼只屬於一位學生、一位老師、一門課和一段接洽對話。使用後寫入 `used_at`。

## 4. 課表與課務

### 4.1 lesson_sessions

正式課表上的一堂課。`starts_at` 必須早於 `ends_at`。狀態為 `scheduled` 或 `cancelled`。

`course_id`、`teacher_id`、`student_id` 都要保存。

### 4.2 change_requests

學生提出約課、請假或調課。狀態為 `pending`、`approved`、`rejected`。

`request_type` 為 `booking`、`leave`、`reschedule`。請假和調課使用 `session_id` 指向原本的課堂。約課和調課使用 `proposed_starts_at`、`proposed_ends_at`。老師同意且時段沒被占用之後，才新增或修改 `lesson_sessions`。

## 5. 練習

### 5.1 practice_recordings

已綁定學生送出的一次錄音。狀態為 `pending`、`processing`、`completed`、`failed`。音檔放在 `uploads/practice/`，資料庫保存 `file_path`。

### 5.2 practice_feedbacks

一筆錄音對應一筆回饋。`recording_id` 唯一。保存 `pitch_score`、`rhythm_score`、`feedback_text`。狀態為 `pending`、`completed`、`failed`。失敗時分數保持空白，不寫成 0。

## 6. 關聯

```text
users
  ├─ teacher_applications
  ├─ auth_identities
  ├─ teacher_profiles
  └─ courses
       ├─ inquiry_conversations
       │    ├─ conversation_messages
       │    └─ binding_codes
       ├─ course_bindings
       ├─ lesson_sessions
       │    └─ change_requests
       └─ practice_recordings
            └─ practice_feedbacks
```

## 7. 原型資料表

下面兩張表的 Model 還在，啟動時可能被建立。只可作為之後 AI 測驗的參考，新功能不要沿用。

| 資料表 | 現況 |
| --- | --- |
| `learning_materials` | 教材上傳原型。只可作為之後 AI 測驗的出題來源，不是完整教材庫 |
| `quizzes` | 測驗原型，只有標題、題目與答案。AI 測驗流程尚未完成 |

舊的工作室綁定（`studios`、`studio_student_bindings`）、舊洽詢（`course_inquiries`）、舊老師課表（`teacher_lesson_sessions`、`teacher_change_requests`）、另一套聊天（`conversations`、`messages`）與老師作業原型（`practice_assignments`、`practice_submissions`、`practice_evaluations`）的程式已經移除。本機資料庫若還留著這些表，不會再被讀寫，可以自行刪除。

尚未建立的正式表包含首頁推薦、課前摘要，以及可審核、可作答的 AI 測驗。這些之後要用 Alembic 新增，不沿用上面的原型表。
