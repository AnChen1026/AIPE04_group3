## 3. 共通欄位與規則

- 一般實體表使用 `id uuid PK`、`created_at timestamptz`、`updated_at timestamptz`；訊息／稽核等不可任意改寫的紀錄可只用 created_at。
- `PK` 是主鍵；`FK` 是外鍵；`NULL` 表示可留空；未註明 NULL 的業務欄位建議必填。
- 時間保存為 timestamptz，網站依 Asia/Taipei 顯示；生日用 date。
- 狀態欄位用 varchar 搭配 CHECK，或沿用專案已有 enum 作法；所有值須有固定定義。
- 外鍵不能只確認 ID 存在，還須確認工作室、老師、學生與課程的範圍一致。
- 業務紀錄優先停用／封存，刪除原則建議 RESTRICT，避免連帶刪掉課表與學習歷史。
- 音檔、教材及 MIDI 的原始位元組放檔案儲存區，DB 保存識別碼及 metadata；不得以永久公開網址暴露學生錄音。
- 下面列核心欄位，共通時間欄位不逐表重列。

## 4. 帳號、工作室及師生關係

### 4.1 users－共用帳號

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 老師與學生共用的登入主體 |
| email | varchar UNIQUE | 正規化後唯一 |
| password_hash | varchar | 帳密登入使用；Google-only 帳號才可為 NULL |
| role | varchar CHECK | teacher、student；單一角色 |
| display_name | varchar | 姓名／顯示名稱 |
| gender | varchar NULL | 選填；值清單待定 |
| birthday | date NULL | 選填，不保存「年齡」避免過期 |
| status | varchar CHECK | active、suspended、deleted |
| last_login_at | timestamptz NULL | 最近登入 |

密碼只保存雜湊；Google 登入的 Token 不存到這張表。註冊時在同一交易建立 users 與對應角色 profile，後端不允許自行改 role。

### 4.2 teacher_profiles－老師資料

`id uuid PK`、`user_id uuid FK → users.id UNIQUE`、`public_name varchar`、`bio text NULL`、`avatar_file_id uuid FK → files.id NULL`。

user 必須為 teacher；公開課程頁可讀取老師明確設為公開的姓名與介紹，不包含私人學生資料。

### 4.3 student_profiles－學生資料

`id uuid PK`、`user_id uuid FK → users.id UNIQUE`。

user 必須為 student；姓名、生日等從 users 取得，不重複保存。原 V1.1 的 line_account_id 不再作為網站登入主體；舊資料是否保留由 Migration 盤點決定。

### 4.4 studios－工作室

`id uuid PK`、`name varchar`、`timezone varchar DEFAULT 'Asia/Taipei'`、`status varchar CHECK(active,suspended,closed)`。

保留原租戶邊界。老師所屬工作室的初始化方式需與既有系統確認，不自行假設所有人共用同一工作室。

### 4.5 studio_members－工作室成員

`id uuid PK`、`studio_id uuid FK → studios.id`、`user_id uuid FK → users.id`、`role varchar`、`status varchar CHECK(active,disabled)`。

UNIQUE(studio_id, user_id)。本版主要使用 owner／teacher；管理 UI 可以先不做，後端仍要依 active 成員驗證權限。

### 4.6 studio_student_bindings－師生關係

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 關係 ID |
| studio_id | uuid FK → studios.id | 所屬工作室 |
| teacher_profile_id | uuid FK → teacher_profiles.id | 指定老師 |
| student_id | uuid FK → student_profiles.id | 學生 |
| requested_by_user_id | uuid FK → users.id | 發起人，只能為這對師生之一 |
| teacher_confirmed_at | timestamptz NULL | 老師確認時間 |
| student_confirmed_at | timestamptz NULL | 學生確認時間 |
| status | varchar CHECK | pending、active、rejected、inactive |

UNIQUE(studio_id, teacher_profile_id, student_id)。發起方送出即記錄自己的確認；另一方確認後才能 active。老師須為該 studio 的有效成員。

**與舊版差異：** 舊 UNIQUE(studio_id, student_id) 改為包含 teacher_profile_id，才能區分同工作室不同老師；需要檢查舊資料再遷移。

## 5. 課程、課堂與申請

### 5.1 courses－鋼琴課程與推廣

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 公開與教學共用課程 ID |
| studio_id | uuid FK → studios.id | 所屬工作室 |
| teacher_profile_id | uuid FK → teacher_profiles.id | 授課老師 |
| title／description | varchar／text | 公開名稱及內容 |
| instrument | varchar CHECK(piano) | 本版固定鋼琴 |
| learning_goals | jsonb | 古典、流行等學習目標／風格 |
| min_level／max_level | varchar | 入門至進階的接受範圍，由後端驗證順序 |
| accepts_level_assessment | boolean | 是否接受程度不確定者先洽詢評估 |
| delivery_mode | varchar CHECK(online,offline,hybrid) | 授課方式 |
| city／district | varchar NULL | 實體課程地區 |
| public_location | text NULL | 老師同意公開的地點資訊 |
| price_per_lesson | numeric CHECK(>=0) | 單堂價格，公開比較用 |
| currency | char(3) DEFAULT TWD | 幣別 |
| duration_minutes | integer CHECK(>0) | 單堂時間，推薦要一同呈現 |
| recruiting_time_tags | jsonb | 可洽詢的招生時段；不是即時預約庫存 |
| status | varchar CHECK(draft,published,paused,archived) | 公開發布狀態 |
| inquiry_enabled | boolean | 是否接受新洽詢 |
| version | integer DEFAULT 1 | 重要資料變更版本 |

公開／推薦候選必須 status=published、inquiry_enabled=true 且工作室有效。封存只停止推廣，不刪既有課堂與學習歷史；是否允許舊修課繼續操作由服務明確檢查。內部排課地點不等於必須公開的 public_location。

索引：(status, instrument)、(studio_id, status)、(teacher_profile_id, status)、(city, district)。舊狀態需正式對照 Migration，不直接覆寫 enum。

### 5.2 enrollments－學生修課

`id uuid PK`、`studio_id uuid FK → studios.id`、`course_id uuid FK → courses.id`、`student_id uuid FK → student_profiles.id`、`status varchar CHECK(active,paused,completed,cancelled)`、`started_at date NULL`、`ended_at date NULL`。

UNIQUE(course_id, student_id)，本版以更新同一關係狀態表示恢復修課。建立時驗證學生與該課老師的關係有效，studio_id 必須與 course 一致。

### 5.3 lesson_sessions－單次課堂

`id uuid PK`、`studio_id uuid FK → studios.id`、`course_id uuid FK → courses.id`、`teacher_profile_id uuid FK → teacher_profiles.id`、`starts_at timestamptz`、`ends_at timestamptz`、`location text NULL`、`status varchar CHECK(scheduled,completed,cancelled)`、`version integer DEFAULT 1`。

CHECK(ends_at > starts_at)。索引：(teacher_profile_id, starts_at)、(studio_id, starts_at)。修改時間增加 version；原時段保留在 change_requests，不因調課丟失歷史。

### 5.4 session_participants－課堂學生

`id uuid PK`、`session_id uuid FK → lesson_sessions.id`、`student_id uuid FK → student_profiles.id`、`enrollment_id uuid FK → enrollments.id`、`attendance_status varchar CHECK(expected,present,absent,leave,cancelled)`。

UNIQUE(session_id, student_id)。驗證 enrollment 的學生與課程都對應本堂。保留此表避免把學生清單塞成字串；是否支援團體課 UI 本次未定。

### 5.5 change_requests－約課／請假／調課申請

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 申請 ID |
| studio_id | uuid FK → studios.id | 授權範圍 |
| enrollment_id | uuid FK → enrollments.id | 提出申請的修課關係 |
| session_id | uuid FK → lesson_sessions.id NULL | 約新課可空；請假／調課必填 |
| requester_user_id | uuid FK → users.id | 本版學生為發起人 |
| request_type | varchar CHECK | booking、leave、reschedule |
| before_payload | jsonb | 原時段與參與狀態快照；新約課為空物件 |
| proposed_payload | jsonb | 希望時間、變更內容；由後端 Schema 驗證 |
| reason | text NULL | 申請原因 |
| status | varchar CHECK | pending、approved、executed、rejected、cancelled、expired、conflict |
| expected_session_version | integer NULL | 建立時的課堂版本；新約課可空 |
| expires_at | timestamptz NULL | 若團隊採到期政策則必填 |
| executed_at | timestamptz NULL | 正式生效時間 |
| client_request_id | uuid | 提交去重鍵 |

UNIQUE(requester_user_id, client_request_id)。索引：(studio_id, status, created_at)、(session_id, status)。

約課建立新 session 與 participant；調課更新既有時間；請假更新該學生的 participant 為 leave，不直接取消其他學生的課堂。第一版不自動扣堂。

### 5.6 change_request_approvals－雙方確認

`id uuid PK`、`change_request_id uuid FK → change_requests.id`、`approver_user_id uuid FK → users.id`、`required_role varchar CHECK(student,teacher)`、`decision varchar CHECK(pending,approved,rejected)`、`decided_at timestamptz NULL`、`decision_note text NULL`。

UNIQUE(change_request_id, required_role)，每筆申請固定學生與授課老師兩筆。學生送出記 approved，老師尚未處理為 pending；不可由學生代填老師同意。

全部同意只是 approved。後端在一筆交易鎖定申請及相關排程資源，重新檢查權限、版本、時段及到期狀態，再更新課堂、申請 executed 與稽核。遇衝突則不部分更新；新約課也要防止併發造成老師或學生時間重疊。

## 6. 檔案、教材與練習

### 6.1 files－共用檔案資訊

`id uuid PK`、`uploaded_by_user_id uuid FK → users.id`、`studio_id uuid FK → studios.id NULL`、`file_type varchar CHECK(midi,audio,material,image)`、`original_name varchar`、`storage_key varchar UNIQUE`、`mime_type varchar`、`size_bytes bigint CHECK(>0)`、`checksum varchar`、`status varchar CHECK(uploading,ready,failed,deleted)`。

每次新上傳產生新檔案，不覆寫同一 storage_key。MVP 僅驗收短曲、單音／簡單雙手、無踏板；老師參考答案必要為 MIDI。先驗證檔案內容與大小，再成為 ready；storage_key 不直接作為公開下載權限。檔案存取從作業／提交／教材的授權關係判斷。

### 6.2 learning_materials－教材

`id uuid PK`、`course_id uuid FK → courses.id`、`teacher_profile_id uuid FK → teacher_profiles.id`、`file_id uuid FK → files.id`、`title varchar`、`description text NULL`、`extracted_text text NULL`、`processing_status varchar CHECK(pending,processing,completed,failed)`、`visibility varchar CHECK(draft,published,archived)`。

檔案屬於該老師的授權工作室；學生只能透過自己的有效修課關係取得 published 教材。教材內容更新時建立新紀錄，保留測驗來源。

### 6.3 practice_assignments－MIDI 練習作業

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 作業 ID |
| enrollment_id | uuid FK → enrollments.id | 指定哪位學生及哪門課 |
| created_by_teacher_id | uuid FK → teacher_profiles.id | 出題老師 |
| reference_file_id | uuid FK → files.id | ready 的參考 MIDI |
| title | varchar | 曲名／作業名稱 |
| instructions | text NULL | 練習說明 |
| reference_metadata | jsonb | 校驗後的速度、拍號、小節邊界及起算位置 |
| due_at | timestamptz NULL | 繳交期限 |
| status | varchar CHECK | draft、published、archived |

本版建議每筆作業指定一位學生，班級批量指派可由後端產生多筆。發布時固定參考檔案及 metadata；之後修正建立新作業。曲首弱起或拍號／速度變化需由 MIDI 解析確定，不能只從音檔秒數硬推小節。

### 6.4 practice_submissions－錄音提交

`id uuid PK`、`assignment_id uuid FK → practice_assignments.id`、`student_id uuid FK → student_profiles.id`、`audio_file_id uuid FK → files.id`、`duration_seconds numeric CHECK(>0)`、`processing_status varchar CHECK(pending,processing,completed,failed)`、`failure_code varchar NULL`、`submitted_at timestamptz`、`client_submission_id uuid`。

UNIQUE(student_id, client_submission_id)。索引：(assignment_id, student_id, submitted_at)。學生必須是作業 enrollment 所指定的人；可有多次提交，每次都保留。分析重試針對同一 submission，不重複建立錄音紀錄。

### 6.5 practice_evaluations－結構化評分與回饋

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 結果 ID |
| submission_id | uuid FK → practice_submissions.id UNIQUE | 一次提交一筆有效結果 |
| pitch_score | numeric NULL CHECK(0–100) | 音高分；未算出可空 |
| rhythm_score | numeric NULL CHECK(0–100) | 節奏分 |
| total_score | numeric NULL CHECK(0–100) | 綜合分；權重待定 |
| extracted_events | jsonb | 辨識的音高、onset、duration、confidence |
| comparison_result | jsonb | 小節／拍位置、漏音、多彈、錯音、節奏偏差及判定依據 |
| scoring_config | jsonb | 本次容許誤差與權重快照 |
| analysis_version | varchar | 音訊分析與評分版本 |
| feedback_text | text NULL | LLM 自然語言回饋 |
| feedback_status | varchar CHECK | pending、completed、failed |
| llm_model | varchar NULL | 使用的語言模型 |
| prompt_version | varchar NULL | 回饋提示詞版本 |

failed 不能以 0 分替代。分析完成但 LLM 失敗時保留結構化評分，僅重試語言回饋。小節回饋必須有可靠對齊資訊；第一版不要求每個音符建一張表，先以 JSONB 保存且固定格式。

## 7. 站內一對一聊天

### 7.1 conversations－聊天室

`id uuid PK`、`binding_id uuid FK → studio_student_bindings.id UNIQUE`、`channel varchar CHECK(web)`、`status varchar CHECK(active,closed)`、`last_message_at timestamptz NULL`、`next_message_seq bigint DEFAULT 1`。

一個師生關係一個聊天室，不跨工作室混合路由。解除關係後禁止新傳訊，舊訊息是否可讀依明確歷史保留政策決定。

### 7.2 conversation_members－成員及讀取進度

`conversation_id uuid FK → conversations.id`、`user_id uuid FK → users.id`、`last_read_seq bigint DEFAULT 0 CHECK(>=0)`。

PK(conversation_id, user_id)。每個聊天室只允許該 binding 的老師及學生兩位；服務在同一交易建立成員。讀取進度只能單調增加且不可超過該聊天室最新序號。

### 7.3 conversation_messages－訊息

`id uuid PK`、`conversation_id uuid FK → conversations.id`、`sender_user_id uuid FK → users.id`、`message_seq bigint`、`content text`、`client_message_id uuid`、`created_at timestamptz`。

UNIQUE(conversation_id, message_seq)、UNIQUE(conversation_id, sender_user_id, client_message_id)。複合 FK(conversation_id, sender_user_id) → conversation_members(conversation_id, user_id)。

發送時驗證有效師生關係；鎖定聊天室的 next_message_seq 分配序號，不能用未鎖定的 MAX+1。未讀數由「message_seq > last_read_seq 且 sender 不是自己」計算，不另存容易失真的未讀總數。

## 8. AI 測驗與作答

### 8.1 quizzes－測驗主檔

`id uuid PK`、`course_id uuid FK → courses.id`、`teacher_profile_id uuid FK → teacher_profiles.id`、`material_id uuid FK → learning_materials.id`、`title varchar`、`status varchar CHECK(generating,draft,published,archived,failed)`、`reviewed_by_user_id uuid FK → users.id NULL`、`reviewed_at timestamptz NULL`、`published_at timestamptz NULL`、`llm_model varchar NULL`、`prompt_version varchar NULL`。

老師審核後才能 published。發布後題目及答案固定；要修改建立新 quiz，原作答持續指向舊版，避免改題後歷史分數失真。

### 8.2 quiz_questions－題目與標準答案

`id uuid PK`、`quiz_id uuid FK → quizzes.id`、`question_type varchar CHECK(single_choice,true_false)`、`question_text text`、`options jsonb`、`correct_answer jsonb`、`explanation text`、`points numeric CHECK(>0)`、`sort_order integer CHECK(>0)`。

UNIQUE(quiz_id, sort_order)。options 使用固定選項 ID，是非題也採固定 true／false 選項；答案必須對應合法選項。老師／AI 端可看答案，學生作答 API 必須排除 correct_answer 與未開放解析。

### 8.3 quiz_attempts－每次測驗

`id uuid PK`、`quiz_id uuid FK → quizzes.id`、`enrollment_id uuid FK → enrollments.id`、`student_id uuid FK → student_profiles.id`、`attempt_number integer CHECK(>0)`、`status varchar CHECK(in_progress,submitted,graded)`、`started_at timestamptz`、`submitted_at timestamptz NULL`、`score numeric NULL`、`max_score numeric NULL`。

UNIQUE(quiz_id, student_id, attempt_number)。驗證 enrollment 是該學生且對應 quiz 的 course。score／max_score 非負，且 score ≤ max_score；可重考次數由服務設定。

### 8.4 quiz_answers－每題學生答案

`id uuid PK`、`attempt_id uuid FK → quiz_attempts.id`、`question_id uuid FK → quiz_questions.id`、`answer_value jsonb`、`is_correct boolean NULL`、`earned_points numeric NULL`。

UNIQUE(attempt_id, question_id)。question 必須屬於 attempt 的 quiz；得分介於 0 與該題 points。交卷、各題評分及總分在同一交易完成，提交後不允許覆寫答案；重複交卷回傳既有結果。

## 9. audit_logs－操作稽核

`id uuid PK`、`studio_id uuid FK → studios.id NULL`、`actor_user_id uuid FK → users.id NULL`、`action varchar`、`target_type varchar`、`target_id uuid NULL`、`result varchar CHECK(success,failure)`、`metadata jsonb`、`created_at timestamptz`。

至少記錄師生加入確認／解除、課務申請審核與執行、作業／教材／測驗發布及權限變更。不保存密碼、Token 或完整檔案內容；一般使用者不能修改稽核紀錄。

## 13. 建表後的最低驗證

- 帳號 email、profile user_id、師生關係及訊息重送鍵不能重複。
- 跨工作室、跨老師與跨學生的課表／錄音／訊息／測驗請求被拒絕。
- 未雙方確認的關係不能授權正式資料存取。
- 約課及調課需檢查師生時段衝突；未確認、逾期或版本衝突時課表不變。
- 老師多次確認同一申請不產生重複課堂；更新失敗全部回滾。
- 錄音提交與指定學生吻合；AI 或 LLM 失敗可以追蹤、重試，不冒充完成結果。
- 作業參考 MIDI 與已發布題目不可覆寫，以保留歷史結果。
- 學生交卷前拿不到正確答案；重複交卷不重複計分。
- 聊天序號、未讀數與斷線重送一致；第三人不能讀聊天室。

## 15. V1.2 推薦與洽詢資料

### 15.1 course_inquiries－站內課程洽詢

`id uuid PK`、`course_id uuid FK → courses.id`、`student_id uuid FK → student_profiles.id`、`recommendation_session_id uuid FK → recommendation_sessions.id NULL`、`message text`、`teacher_response text NULL`、`responded_by_user_id uuid FK → users.id NULL`、`responded_at timestamptz NULL`、`status varchar CHECK(new,responded,closed,cancelled)`、`client_request_id uuid`。

UNIQUE(student_id, client_request_id)。索引：(course_id, status, created_at)、(student_id, created_at)。必須登入學生後送出；老師只讀自己課程的洽詢。MVP 一次洽詢保存一份回覆，不以正式聊天室授權替代。學生可再提出加入，雙向同意後建立正式修課。

學生聯絡資訊以帳號必要資訊取得，不沿用舊版訪客 phone／LINE 識別；洽詢不代表付款、報名或師生確認。送出時再驗證課程仍公開且可洽詢。

### 15.2 recommendation_sessions－首頁對談

`id uuid PK`、`user_id uuid FK → users.id NULL`、`anonymous_token_hash varchar NULL`、`source varchar CHECK(homepage)`、`status varchar CHECK(collecting,clarifying,ready,recommended,no_match,ended)`、`clarification_count smallint CHECK(0–2)`、`model_version varchar NULL`、`ranking_version varchar`、`expires_at timestamptz`。

匿名 token 只存雜湊，用於授權短效 session；不收集無關身份。user_id 或匿名身份必須有一者有效。補問限制包含所有搜尋及程度問題，取代舊版只計程度補問的草案。

### 15.3 recommendation_preferences－條件與初步程度

`id uuid PK`、`recommendation_session_id uuid FK → recommendation_sessions.id UNIQUE`、`instrument varchar CHECK(piano)`、`learning_goal text NULL`、`experience_text text NULL`、`assessed_level varchar CHECK(beginner,elementary,intermediate,advanced,uncertain)`、`level_confidence numeric NULL CHECK(0–1)`、`skill_evidence jsonb`、`budget_min／budget_max numeric NULL`、`currency char(3)`、`city／district varchar NULL`、`delivery_modes jsonb`、`time_preferences jsonb`、`unknown_fields jsonb`。

預算非負、上限不得小於下限；未知保持 NULL／未知清單，不冒充完全符合。此資料為一次找課需求，不等於長期個人偏好或正式檢定程度。

### 15.4 recommendation_results－有效推薦快照

`id uuid PK`、`recommendation_session_id uuid FK → recommendation_sessions.id`、`course_id uuid FK → courses.id`、`rank integer CHECK(>0)`、`total_score numeric`、`score_breakdown jsonb`、`reason_text text`、`mismatch_notes jsonb`、`course_snapshot jsonb`。

UNIQUE(recommendation_session_id, course_id)、UNIQUE(recommendation_session_id, rank)。分數尺度依 ranking_version 固定。快照僅保存必要公開欄位，詳情／洽詢再驗證課程有效性；不使用外部訂閱、原工作室優先或付費推廣排序。

## 16. lesson_preparation_summaries－老師課前練習摘要

| 欄位 | 型別／限制 | 說明 |
| --- | --- | --- |
| id | uuid PK | 摘要 ID |
| session_participant_id | uuid FK → session_participants.id UNIQUE | 本堂的指定學生；一筆目前有效摘要 |
| generated_by_user_id | uuid FK → users.id | 有授課權限的老師 |
| previous_session_id | uuid FK → lesson_sessions.id NULL | 同修課前一堂已完成課 |
| window_start／window_end | timestamptz | 保存實際 [起點, 終點) |
| window_basis | varchar CHECK(previous_lesson,enrollment_start,enrollment_created) | 首堂起算依據明示 |
| session_version | integer | 生成時的本堂版本，用於偵測改期 |
| statistics | jsonb | 提交次數／日期、成功／失敗／處理中數、可比表現及反覆問題 |
| source_submission_ids | jsonb | 窗口內平台提交來源 ID，格式由後端固定 |
| source_evaluation_ids | jsonb | 實際採用的有效分析 ID |
| source_fingerprint | varchar | 窗口、課堂版本、來源／狀態／評分版本的計算指紋 |
| summary_text | text NULL | 老師用自然語言摘要 |
| status | varchar CHECK(pending,processing,completed,no_records,failed) | 無紀錄與失敗分開 |
| generated_at | timestamptz NULL | 生成時間；沒有紀錄可直接完成統計 |
| llm_model／prompt_version | varchar NULL | 模型及提示詞版本 |
| failure_code | varchar NULL | 處理失敗原因代碼 |

CHECK(window_end >= window_start)。透過 participant → enrollment／session 驗證同學生、課程、老師與工作室；老師不得傳任意來源 ID 要求摘要。

窗口：同 enrollment、ends_at 不晚於本堂 starts_at 的最近一堂 completed 課 ends_at 起，至 min(生成時 now, 本堂 starts_at)，按 submitted_at 取樣。首堂用 started_at 的 Asia/Taipei 起始日時間；若 NULL 則用 enrollment.created_at 並明示。尚未分析完的提交計入平台紀錄數，但不當成已完成評分。

同作業／同參考／可比較評分版本才比較分數。無平台紀錄不代表沒有實際練習；摘要須包含來源與未知處。只有老師能讀本表；學生看自己的 practice_evaluations，不自動取得老師備課建議。

老師開啟課堂頁才產生／更新；重新計算來源指紋，比對後可回傳 needs_refresh。課堂改期或新分析完成時舊摘要標示需要更新；不要求課前排程。重試更新同一筆，防止並行生成重複摘要，失敗仍可查看個別紀錄。

## 17. V1.2 建立與驗證補充

先建立原 25 張的必要基礎及擴充 courses；再建 recommendation_sessions → recommendation_preferences／results → course_inquiries；participant 及練習分析存在後建 lesson_preparation_summaries。course_inquiries 為弱關聯來源，匿名 session 到期不應刪除洽詢。

新增驗證：公開推薦不洩漏私人欄位；其他樂器不能建立課程；封存課程不能新洽詢；匿名 session 不可互讀；兩題補問限制一致；課前窗口不混入其他修課；新結果及改期能使摘要需要更新；無紀錄、失敗、低信心正確表達。

本文件是完整欄位設計草案，不代表已執行 Migration。
