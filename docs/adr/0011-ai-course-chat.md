# AI 找課改成會聊天的顧問（課程 RAG）

原本的 AI 找課只讓模型把一句話拆成六個條件欄位，回覆全是固定句子，使用者覺得它不會聊天、聽不懂意思，也回答不了「怎麼約課」這類問題。所以首頁右下角的 AI 找課改成聊天顧問：先從已發布課程檢索最相關的六門，再讓模型只根據這些課程和一份平台說明回答。這放寬 [0007](0007-ai-search-and-rag-boundaries.md)「推薦理由不交給語言模型」的規定；課程來源仍然只有 `courses` 裡已發布的課。

**模型可以說話，但課程事實以卡片為準。** 回覆附上的課程卡片一律由資料庫組成，只有回覆寫到課名的課才附卡片；同名的課要連老師名字一起寫到才附，否則不附。卡片再由程式核對：超過學生說的預算、實體課不在學生說的地區、回覆寫給這門課的價格和資料不同，都在卡片上提醒。模型偶爾會說錯數字，所以價格、地區、上課方式看卡片。

**檢索沿用原本的找課規則。** 上課方式只存 `online`、`in_person`（migration 023 把早期種子資料的中文值轉掉，「線上與實體」歸為實體，並加上檢查限制），篩選才比對得到。學生說得出來的程度、曲風、上課方式、地區、預算、時段，用原本的條件解析與篩選確實篩過，符合的課排在前面；不夠六門才補其他相近的課，模型才能說明哪裡不符合、建議放寬什麼。排序沿用 bge-m3 課程索引；沒有閘道或索引時維持最新課程的順序。

**對話不存資料庫。** 對話留在瀏覽器，每次把整段對話送上來（最多 20 則），重新整理就清掉；後端不保存訪客說的話。回覆走 `llm` 模組的 `course_chat` 功能，跟著 `COURSE_CHAT_LLM_PROVIDER`，沒設就跟 `LLM_PROVIDER`，所以本機千問或 OpenAI 都能用。

原本的條件式找課（`/api/recommendations`）程式保留，前端不再呼叫；要切回去只要改回前端元件。
