# 鋼琴教學管理與課程推廣平台 SRS

版本：V1.2；更新：2026-09-30；需求依據：PRD V1.2。所有功能透過網站，僅鋼琴。

## 1. 功能需求與驗收

| ID | 系統必須提供 | 驗收重點 |
| --- | --- | --- |
| AUTH-01 | 師生註冊、登入、登出及角色分流 | 單一角色；學生不能呼叫老師管理功能 |
| AUTH-02 | 基本資料與最小蒐集 | 姓名必填；性別／生日建議選填 |
| CAT-01 | 公開課程列表、篩選及詳情 | 只公開有效工作室的 published、可洽詢鋼琴課 |
| CAT-02 | 老師管理課程及公開程度、風格、方式、地區、單堂價格、時段資訊 | 不完整資料不能宣稱完全匹配；封存後退出推薦 |
| REC-01 | 自然語言需求抽取 | 固定輸出格式；未知不臆造；拒絕其他樂器需求並說明範圍 |
| REC-02 | 鋼琴程度推估與必要追問 | 入門／初階／中階／進階／不確定；全對談最多兩題 |
| REC-03 | DB 篩選、規則排序及理由 | 只回傳真實有效課程；無結果可選擇修改條件 |
| INQ-01 | 註冊學生後站內洽詢與老師回覆 | 記錄目標課程、內容與回覆；不等同報名 |
| BIND-01 | 雙向確認正式師生關係 | pending 無私人教材／錄音權限；同意後 active |
| STU-01 | 老師查看自己學生及所授課學習紀錄 | 不讀取學生在別位老師處的紀錄 |
| SCH-01 | 老師排課、師生個人課表 | 開始早於結束；避免師生時間重疊 |
| CHG-01 | 學生约課／請假／調課與老師審核 | 送出後正式課表不變，確認且再次驗證後才生效 |
| CHG-02 | 異動去重、版本檢查與交易 | 重複送出不重複排課；失敗全部回滾 |
| CHAT-01 | 正式師生一對一即時文字與歷史 | 保存後傳送，重送去重，斷線能補讀 |
| CHAT-02 | 每人成員讀取進度及未讀數 | 未讀只計對方訊息；第三人不可查詢 |
| FILE-01 | 受保護的 MIDI、錄音與教材上傳 | 驗證實際內容、大小及歸屬；檔案不永久公開 |
| PRA-01 | 老師發布指定學生的 MIDI 練習作業 | 參考 MIDI 經校驗；發布後固定參考與小節資訊 |
| PRA-02 | 學生麥克風錄音、回放、確認送出及歷史 | 權限拒絕有提示；只能送自己的作業 |
| PRA-03 | 錄音後分析音符事件及對齊參考 | 固定短曲、單音／簡單雙手、無踏板測試 |
| PRA-04 | 分開計算音高、漏音、多彈、節奏差異 | 容許誤差有版本；結果能追溯小節／拍位置 |
| PRA-05 | LLM 產生學生回饋 | 只用評分 JSON；不編造音符；音正確拍不齊需分開描述 |
| PRA-06 | 待處理／處理中／完成／失敗與重試 | 失敗不顯示 0 分；LLM 失敗保留結構化分析 |
| PRE-01 | 老師在課堂頁產生／更新課前摘要 | 同學生、老師、修課的前堂課後至本堂課前資料 |
| PRE-02 | 顯示摘要來源、期間及生成時間 | 来源提交可追溯；有新結果／改期時標記需要更新 |
| PRE-03 | 無紀錄／低信心／不可比較的保守摘要 | 不能說無平台紀錄等於沒練；不同曲目不直接比總分 |
| MAT-01 | 教材上傳、內容抽取及可見性 | 學生只能讀自己課程的已發布教材 |
| QUIZ-01 | AI 產生選擇／是非題草稿 | 教材為來源；生成失败可重試；不直接發布 |
| QUIZ-02 | 老師審核題幹、答案及解析後發布 | 發布版本固定；改題建立新版 |
| QUIZ-03 | 學生作答、交卷及後端標準答案批改 | 交卷前不外洩答案；同一交卷不重複計分 |
| OPS-01 | 權限、稽核、限流、受控錯誤及備份 | 不記錄 secret；異常可追蹤；備份能還原 |

## 2. 核心狀態

| 領域 | 狀態及規則 |
| --- | --- |
| 課程 | draft → published → paused／archived；只有 published 且可洽詢才公開推薦 |
| 洽詢 | new → responded → closed／cancelled；不自動建立修課 |
| 師生關係 | pending → active／rejected；active 可停用為 inactive |
| 課務申請 | pending → approved → executed；亦可 rejected／cancelled／expired／conflict |
| 練習分析 | pending → processing → completed／failed；重試針對同一提交 |
| 課前摘要 | pending → processing → completed／failed；沒有練習紀錄為 no_records |
| 測驗 | generating → draft → published；生成可 failed，發布後可 archived |
| 作答 | in_progress → submitted → graded；提交後答案不可覆寫 |

approved 不等於已改課，只有 executed 代表正式資料成功更新。

## 3. 資料與 AI 邊界

推薦與學習評估採兩種程度用途：首頁自述程度是找課推估；錄音結果是該次作業的音高／節奏表現。不得把一次短曲分數直接當成正式鋼琴程度或覆蓋找課標籤。

音訊分析、規則計分與 LLM 文字生成分開。AI 不取得任意 DB 讀寫權、不決定權限、不直接改課表。課前摘要接收後端已篩選的統計與來源摘要，不送入無關聯絡／付款個資。

## 4. 非功能需求

- 網站與 API 使用 HTTPS；網站錄音於受支持的安全環境及使用者授權下運作。
- 業務查詢強制身份、師生／修課關係及工作室範圍。
- 慢速音訊／LLM 工作不阻塞一般課務操作；前端可重新取得持久化狀態。
- 快速回饋的秒數目標待固定檔案長度、曲目、模型及實際部署壓測後定案，不宣稱零延遲。
- 保存分析版本、提示詞版本、參考答案及摘要來源；必要重試具冪等性。
- 原始錄音／聊天／摘要保存期限與刪除政策待定；不擅自宣告特定期限。

## 5. 核心驗證情境

1. 想學流行鋼琴但描述模糊時最多補問兩題；只推薦 DB 的公開有效課程。
2. 訪客洽詢時轉註冊；登入後能回到原目標課程，老師可站內回覆。
3. 洽詢學生尚未建立正式關係時不能讀老師其他學生紀錄。
4. 學生錄音的已知錯音、漏音與節奏不齊被分別顯示；辨識不確定不過度責備。
5. 老師課前摘要只含同修課時間窗口資料；無平台紀錄時不推論學生沒練。
6. 比較不同 MIDI／曲目的結果時不生成無依據的進步判斷。
7. 課堂改期、新錄音分析完成後舊摘要需要更新；重試不重複結果。
8. 跨學生讀取錄音、摘要、訊息及測驗被拒絕；答案交卷前不可見。
9. 老師同意時目標時段已被占用，申請 conflict，原課表完整保留。

本文件定義應有行為，並未聲稱上述測試已執行；API 契約及現有實作需另核對程式碼。
