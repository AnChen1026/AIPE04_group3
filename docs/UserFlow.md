## 1. 角色與入口

| 角色 | 入口 | 主要流程 |
| --- | --- | --- |
| 訪客 | 公開首頁 | 瀏覽課程、AI 推薦、平台 QA、註冊、洽詢 |
| 學生 | 學生頁面 | 課表、申請、聊天、測驗、鋼琴練習 |
| 老師 | 老師後台 | 課程、學生、課表、申請、聊天、教材與任務 |
| 平台管理員 | 管理後台 | 帳號、內容、異常與稽核 |

## 2. 註冊與固定角色

```mermaid
flowchart TD
    A[進入註冊頁] --> B[填寫 Email 與密碼]
    B --> C{選擇角色}
    C -->|老師| D[建立 teacher 帳號]
    C -->|學生| E[建立 student 帳號]
    D --> F[建立或加入工作室]
    F --> G[進入老師後台]
    E --> H[完成學生基本資料]
    H --> I[進入學生頁面]
```

- MVP 角色建立後不可自行切換。
- 如選錯角色，使用者需聯繫平台管理員；不得只改前端欄位。

## 3. 首頁課程與 AI 推薦

```mermaid
flowchart TD
    A[進入首頁] --> B{使用方式}
    B -->|直接瀏覽| C[搜尋與套用篩選]
    B -->|自然語言| D[AI 抽取需求與程度證據]
    D --> E{資訊足夠?}
    E -->|否且未滿 2 題| F[追問一個關鍵問題]
    F --> D
    E -->|是或達上限| G[後端查詢有效課程]
    C --> G
    G --> H[規則排序]
    H --> I[顯示理由與限制]
    I --> J[查看詳情]
    J --> K[登入或註冊學生帳號]
    K --> L[送出課程洽詢]
```

AI 若收到平台使用問題，改由核准的 QA 知識回答；無答案時提供說明入口，不得捏造。

## 4. 師生關係建立

### 4.1 課程洽詢

```mermaid
sequenceDiagram
    participant S as 學生
    participant P as 平台
    participant T as 老師
    S->>P: 送出課程洽詢
    P-->>T: 顯示待處理洽詢
    T->>P: 接受或拒絕
    alt 接受
        P->>P: 建立修課／師生關係
        P-->>S: 顯示已建立關係
    else 拒絕
        P-->>S: 顯示未建立關係
    end
```

### 4.2 老師邀請

```mermaid
sequenceDiagram
    participant T as 老師
    participant P as 平台
    participant S as 學生
    T->>P: 建立限時邀請
    P-->>T: 回傳邀請碼／連結
    S->>P: 登入後開啟或輸入邀請
    P-->>S: 顯示工作室、老師與課程
    S->>P: 確認加入
    P->>P: 驗證期限、次數與重複關係
    P-->>S: 建立完成或顯示失敗原因
```

## 7. 請假／調課流程

```mermaid
stateDiagram-v2
    [*] --> draft
    draft --> pending: 學生送出
    pending --> approved: 老師同意
    pending --> rejected: 老師拒絕
    pending --> proposed: 老師提出替代時段
    pending --> withdrawn: 學生撤回
    pending --> expired: 超過期限
    proposed --> pending: 學生接受替代方案
    approved --> executed: 重驗通過並更新課表
    approved --> conflict: 版本或時段衝突
    executed --> [*]
    rejected --> [*]
    withdrawn --> [*]
    expired --> [*]
    conflict --> [*]
```

1. 學生選擇自己的課堂與請假／調課類型。
2. 系統顯示原課堂、申請內容及可能影響。
3. 學生送出後，正式課表仍不變。
4. 老師同意時，後端重新檢查課堂版本、權限及衝突。
5. 通過才以單一交易更新課堂與申請狀態。

## 8. 一對一即時聊天

```mermaid
sequenceDiagram
    participant S as 學生頁面
    participant API as FastAPI
    participant DB as PostgreSQL
    participant T as 老師後台
    S->>API: 傳送文字與 client_message_id
    API->>API: 驗證有效師生關係與對話成員
    API->>DB: 寫入訊息
    DB-->>API: 回傳 message_id
    API-->>S: 確認已送出
    API-->>T: WebSocket 推送新訊息
    T->>API: 更新已讀位置
    API->>DB: 保存 last_read_message_id
```

- WebSocket 中斷不等於訊息遺失；重連後依最後訊息位置補抓。
- 未讀數由後端根據已讀位置計算。
- MVP 僅支援文字訊息。

## 9. AI 測驗流程

```mermaid
flowchart TD
    A[老師上傳教材] --> B[檔案驗證與文字擷取]
    B --> C[AI 產生選擇／是非題草稿]
    C --> D[老師預覽與修改]
    D --> E{是否發布?}
    E -->|否| D
    E -->|是| F[指派學生與期限]
    F --> G[學生作答並提交]
    G --> H[依核准答案自動批改]
    H --> I[顯示分數與允許的解析]
```

若 AI 無法從教材取得足夠依據，題目保留為需人工補充，不能自動發布。

## 10. AI 鋼琴練習流程

```mermaid
flowchart TD
    A[老師建立練習任務] --> B[上傳樂譜圖片或參考音檔]
    B --> C[參考資料預處理]
    C --> D[學生開啟任務]
    D --> E[授權麥克風]
    E --> F[錄音、播放或重錄]
    F --> G[送出分析任務]
    G --> H[音訊特徵與小節／區段對齊]
    H --> I{信心足夠?}
    I -->|是| J[產生小節級概略回饋]
    I -->|否| K[降級回饋／請重錄／交老師查看]
    J --> L[學生與老師查看結果]
    K --> L
```

可接受語句：

- 「第 4 小節速度稍慢，可以搭配節拍器再試一次。」
- 「第 8 小節錯音較集中，建議放慢速度確認樂譜。」

不可在證據不足時輸出：

- 精密到秒或音分的斷言。
- 將環境雜音直接判定為學生能力問題。
- 正式檢定等級或保證性結論。

## 11. 主要例外

| 例外 | 處理 |
| --- | --- |
| 邀請過期或撤銷 | 不建立關係，提示向老師索取新邀請 |
| 老師拒絕洽詢 | 不建立關係，保存處理狀態 |
| 課表申請等待期間時段被占用 | 標記 conflict，不部分更新 |
| WebSocket 中斷 | 自動重連並以 REST 補抓 |
| 重複送出聊天訊息 | 依 client_message_id 去重 |
| 教材無法解析 | 顯示失敗原因，允許老師更換檔案 |
| AI 題目缺乏教材依據 | 標記需人工修改，不允許直接發布 |
| 麥克風被拒絕 | 顯示瀏覽器權限說明，不建立空錄音 |
| 鋼琴錄音雜音過高 | 要求改善環境或重錄 |
| 小節對齊信心不足 | 降級為時間區段／整體回饋並標示限制 |
