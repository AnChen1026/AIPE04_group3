# 鋼琴智能推薦與程度辨識流程設計

版本 V1.2；更新 2026-09-30；對應 PRD／SRS V1.2。

## 1. 範圍

平台首頁為訪客提供鋼琴課程推薦及初步程度辨識。註冊後可站內洽詢；第一版不做登入後長期偏好推薦、付費競價排序、多樂器或跨工作室訂閱資格。

## 2. 分工

| 工作 | 執行者 |
| --- | --- |
| 首頁推薦與客服 | Ollie；後端串接由禹銨負責 |
| 理解自然語言、學習目標與經驗 | LLM |
| 產生格式固定的需求及必要追問 | LLM，由後端驗證 |
| 程度規則、未知處理、追問次數 | 後端 |
| DB 候選與適配排序 | 後端 |
| 基於真實候選生成推薦理由 | LLM 或既有文字模板 |

LLM 不自由編課程、不直連任意 DB，也不把錄音作業分數直接當成正式程度。

## 3. 條件與程度

| 欄位 | 來源／處理 |
| --- | --- |
| instrument | 固定 piano；其他樂器告知本版不提供 |
| learning_goal | 古典、流行、自彈自唱、興趣、考級等自述目的 |
| experience／evidence | 學過多久、能完成什麼、讀譜／雙手／節奏能力等自述證據 |
| assessed_level | beginner、elementary、intermediate、advanced、uncertain |
| confidence | 紀錄可信程度與未知資訊；不宣稱正式能力檢定 |
| location／delivery_modes | 城市／行政區、線上或實體 |
| budget | 同一幣別、單堂價格與課長；未提供保持未知 |
| time_preferences | 希望時段；課程招生時段標籤不代表即時空檔 |

入門：幾乎無經驗；初階：能處理少量基礎內容但不穩定；中階：能穩定完成一般內容；進階：能處理較複雜技巧與自主學習；不確定：證據不足或能力不均。

程度主要看獨立完成新曲的能力，不只靠年數或單首曲名。鋼琴可輔以讀譜、雙手協調與節奏的證據；本版不建立全樂器規則庫。

## 4. 流程

1. 收到文字，建立短效匿名推薦 session；已登入可关聯 users，但不保存無關個資。
2. LLM 抽取需求，後端驗證 JSON 及限制。
3. 優先利用已有描述；只有缺失會改變推薦結果才問。
4. **整次對談最多追問兩題，包含搜尋與程度補問。** 這取代舊草案只計程度題的規則。
5. 補問後仍不確定則保留 uncertain／未知，不繼續追問。
6. 取得有效工作室、published 且 inquiry_enabled 的鋼琴課程。
7. 已明確提出的必要條件作硬篩選；未知條件不假裝符合。
8. 規則排序，再產生理由、初步程度與必要不符合提示。
9. 顯示課程詳情，洽詢時要求學生註冊／登入並回到該課。
10. 保存結構化條件、真實候選結果及規則版本以供驗證；匿名資料保留期限待定。

## 5. 排序草案

| 因子 | 初始建議權重 |
| --- | ---: |
| 鋼琴學習目標／風格 | 30% |
| 程度適配 | 25% |
| 希望時間 | 20% |
| 地區／授課方式 | 15% |
| 單堂預算 | 10% |

權重沿用舊版作為待驗證初值。未知因子不給滿分；可按有效因子重新正規化並顯示未知處，具體公式待工程確認。未知程度時只推可接受初評的課程，不宣稱程度完全匹配。

本版不要求原工作室優先、訂閱才能推薦或推廣優先。課程公開曝光即為推廣能力，非付費廣告系統。

## 6. 無結果

明確告知沒有符合項目；讓使用者選擇放寬時間、預算或地區。不得默默改掉使用者的硬條件，也不能推薦已封存課程。部分符合時逐項說明差異。

## 7. 驗收例

- 「沒有學過，想學流行鋼琴」：辨識入門與目標，不要求無用的曲目證照資料。
- 「學三年但雙手常卡住」：不足以直接判進階，必要時詢問完成新曲的能力。
- 「想學吉他」：说明平台目前只提供鋼琴，不回傳鋼琴假符合結果。
- 沒有預算：保持未知；不宣稱所有候選都符合預算。
- DB 課程被封存：下一次取詳情／洽詢再驗證，不能使用推薦快照直接成立報名。

## 8. 與練習功能的關係

本模組是找課階段的自述程度辨識。學生登入後的錄音分析是指定 MIDI 作業的客觀差異資料；課前摘要彙整該修課練習。三者分開保存，未經專門規則與老師確認，不自動合成正式程度。
