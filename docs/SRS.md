## 1. 系統範圍

系統包含四個介面：

1. 公開平台：課程展示、搜尋、AI 課程推薦與平台 QA。
2. 老師後台：課程、學生、課表、異動、聊天、教材、測驗與練習任務。
3. 學生頁面：課表、異動申請、聊天、測驗與鋼琴練習。
4. 平台管理後台：帳號、內容、異常、檔案與稽核。

## 3. 功能需求

### 3.1 帳號與權限

| ID | 需求 | 優先級 |
| --- | --- | --- |
| FR-AUTH-01 | 系統必須支援 Email 註冊、登入、登出及忘記密碼。 | Must |
| FR-AUTH-02 | 註冊時必須選擇 teacher 或 student，MVP 建立後不可自行切換。 | Must |
| FR-AUTH-03 | 老師首次登入必須建立或加入一個工作室。 | Must |
| FR-AUTH-04 | 學生與老師 API 必須由後端依帳號角色拒絕越權。 | Must |
| FR-AUTH-05 | 工作室資料必須依登入者的有效成員關係與 `studio_id` 限制。 | Must |
| FR-AUTH-06 | 重設密碼憑證必須限時、一次性並可撤銷。 | Must |
| FR-AUTH-07 | 系統必須記錄登入、權限、邀請與高風險操作。 | Must |

### 3.2 公開課程與 AI 客服

| ID | 需求 | 優先級 |
| --- | --- | --- |
| FR-CAT-01 | 公開首頁只顯示已發布且可洽詢的課程。 | Must |
| FR-CAT-02 | 使用者可依關鍵字、類型、地區、預算、時間、方式與程度篩選。 | Must |
| FR-CAT-03 | 課程詳情須顯示老師、工作室、程度、方式、地點、價格與洽詢入口。 | Must |
| FR-AI-01 | AI 必須抽取課程類型、目標、經驗、程度、時間、地區、方式與預算。 | Must |
| FR-AI-02 | AI 對談最多追問 2 題；未知值不得臆造。 | Must |
| FR-AI-03 | AI 推薦候選只能來自後端提供的有效課程。 | Must |
| FR-AI-04 | 排序由後端規則執行，結果須包含推薦理由與不符合提示。 | Must |
| FR-AI-05 | AI 必須能回答經核准的平臺功能 QA；找不到答案時不得捏造。 | Must |
| FR-AI-06 | 登入學生可使用 AI 客服，但 MVP 不建立長期個人化推薦檔案。 | Must |

| ID | 需求 | 優先級 |

| FR-COURSE-02 | 課程須包含類型、目標、程度、方式、地點、價格、時長與狀態。 | Must |
| FR-REL-01 | 學生可從課程頁送出洽詢，老師可接受或拒絕。 | Must |
| FR-REL-02 | 洽詢被接受時，系統才可建立正式師生／修課關係。 | Must |
| FR-REL-03 | 老師可建立限時、可撤銷、限次邀請碼或邀請連結。 | Must |
| FR-REL-04 | 學生登入並確認邀請資訊後，系統才可建立正式關係。 | Must |
| FR-REL-05 | 重複接受同一工作室、老師、學生與課程關係不得產生重複資料。 | Must |
| FR-REL-06 | 老師只能查看自己工作室的學生與有效關係。 | Must |

| ID | 需求 | 優先級 |
| --- | --- | --- |
| FR-SCH-01 | 老師可建立課堂並指定課程、老師、學生、開始及結束時間。 | Must |

| FR-SCH-03 | 系統必須避免相同老師或學生於同時間重複排課。 | Must |
| FR-SCH-04 | 學生只能查看自己的有效課堂。 | Must |
| FR-CHG-01 | 學生可針對自己的課堂提出請假或調課並留言。 | Must |
| FR-CHG-02 | 申請送出後正式課表保持不變，直到老師確認。 | Must |
| FR-CHG-03 | 老師可同意、拒絕或提出替代時段。 | Must |
| FR-CHG-04 | 老師同意時，系統須重新驗證權限、版本與時段衝突。 | Must |
| FR-CHG-05 | 課表更新與申請狀態更新必須在同一資料庫交易完成。 | Must |
| FR-CHG-06 | 拒絕、撤回、逾期或衝突申請不得修改正式課表。 | Must |

| FR-CHAT-02 | 系統必須支援即時文字訊息。 | Must |

| FR-CHAT-06 | 非成員不得讀取、訂閱或發送對話訊息。 | Must |

| FR-QUIZ-01 | AI 只能根據指定教材產生單選題與是非題草稿。 | Must |

### 3.7 AI 鋼琴練習回饋

| ID | 需求 | 優先級 |
| --- | --- | --- |
| FR-PRAC-01 | 老師可建立練習任務並上傳樂譜圖片或參考音檔。 | Must |
| FR-PRAC-02 | 學生須明確授權後，瀏覽器才可啟用麥克風錄音。 | Must |
| FR-PRAC-03 | 錄音須顯示開始、停止、播放、重錄與送出狀態。 | Must |
| FR-PRAC-04 | 系統須以背景任務處理參考資料、錄音及小節／區段對齊。 | Must |

## 4. 非功能需求

| ID | 類別 | 需求 |
| --- | --- | --- |
| NFR-SEC-01 | 安全 | 全部傳輸使用 HTTPS；密碼使用成熟雜湊；Secret 不得進 Git、前端或 Log。 |
| NFR-SEC-02 | 安全 | 後端強制角色與租戶權限，不依賴 UI 隱藏。 |
| NFR-SEC-03 | 安全 | 上傳檔案須限制副檔名、MIME、大小並掃描惡意內容。 |
| NFR-PRIV-01 | 隱私 | 麥克風錄音前取得明確授權，並說明用途與保留期限。 |
| NFR-PERF-01 | 效能 | 不含 AI／音訊背景處理的一般 API，測試環境 P95 目標低於 1 秒。 |
| NFR-PERF-02 | 效能 | 聊天訊息持久化後的即時通知目標在正常網路下 2 秒內。 |
| NFR-REL-01 | 可靠性 | 訊息、邀請接受、申請確認、測驗提交與分析任務須具冪等性。 |
| NFR-REL-02 | 可靠性 | 背景任務失敗不得產生半完成正式資料，且可安全重試。 |
| NFR-MAIN-01 | 維護性 | Router → Service → Repository → Database 分層一致。 |
| NFR-OBS-01 | 可觀測性 | 記錄登入失敗、越權拒絕、聊天錯誤、AI 失敗與音訊處理時間。 |
| NFR-UX-01 | 易用性 | 狀態不可只靠顏色表達；錄音、上傳與分析均有明確進度。 |
| NFR-AI-01 | AI 安全 | AI 輸出須經固定 Schema 驗證，不能直接決定權限或寫入正式課表。 |

## 5. 資料一致性要求

- 全部 ID 由後端產生或驗證。
- 時間以 `timestamptz` 儲存，顯示預設 `Asia/Taipei`。
- 課堂結束時間必須晚於開始時間。
- 邀請碼只保存雜湊，並具到期、次數及撤銷狀態。
- 同一申請只能完成一次老師決策；重送不得重複修改課表。
- 同一測驗嘗試只能提交一次；重送回傳原結果。
- 同一聊天 client message ID 只能建立一筆訊息。
- 軟刪除或停用資料不得出現在公開推薦與新指派中。

## 7. 核心驗收測試

1. 學生帳號呼叫老師課程建立 API，必須回傳拒絕。
2. A 工作室老師以猜測 ID 讀取 B 工作室資料，必須回傳拒絕。
3. 過期／撤銷邀請不可建立師生關係；重送接受請求不重複建立。
4. 學生送出調課後課堂不變；老師同意後才在交易中更新。
5. 非聊天成員無法連線該對話 WebSocket 或讀取歷史。
6. WebSocket 斷線期間訊息可於重連後補抓，且無重複訊息。
7. AI 生成題目未發布前學生不可查看；發布後自動計分正確。
8. 修改已有作答的測驗會建立新版本，不改變舊分數。
9. 未允許麥克風時不得開始錄音；拒絕權限時顯示可理解提示。
10. 低信心鋼琴分析不得輸出精密音高或時間斷言。
11. 惡意或不允許檔案不得進入 AI／音訊處理流程。
12. AI 推薦中的課程 ID 必須存在且當下可公開洽詢。
