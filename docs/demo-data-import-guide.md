# 示範教師與課程資料是怎麼建立的？

網站上這批假資料共有 **226 位教師、426 門課程**，用來展示課程、測試搜尋及 AI 找課。教師姓名與課程內容都是專案準備的示範資料，不是真實老師的招生資訊。

整個過程可以想成「準備教材 → 編好教師與課程清單 → 放進網站資料庫」。其中，真正把資料放進資料庫的主程式是 **`scripts/import_demo_data.py`**。

## 一、先看整個流程

```text
準備好的課程主題與原有資料清單
          ↓
build_demo_catalog.py
編排教師姓名、專長、課名與介紹
          ↓
aicourse-demo.json
保存完整的教師與課程清單
          ↓
import_demo_data.py
檢查資料，放進網站資料庫
          ↓
網站可以顯示課程，也可以搜尋課程
          ↓
index_course_embeddings.py（另外執行）
讓 AI 找課能依意思相近的程度排列課程
```

這些步驟不需要每次開網站都執行。資料已經放好後，網站直接從資料庫讀取即可。

## 二、每個 Python 檔負責什麼？

### `build_demo_catalog.py`：編輯教師與課程內容

位置：[scripts/build_demo_catalog.py](../scripts/build_demo_catalog.py)

可以把它想成「課程清單的編輯」。它會讀取原有教師、課程清單，再搭配事先準備好的課程主題，整理出目前這批內容。

它主要負責：

- 從程式內準備好的中文、英文名字中安排教師姓名。
- 安排入門、初階、中階、進階的課程與主題。
- 讓老師的專長、教法與他開的課互相配合。
- 編出課名、課程介紹、先備能力、練習安排與上課方式。
- 檢查 426 個課名與 226 個教師顯示名稱沒有重複。

例如，一位老師被安排教授爵士主題，他的專長與課程介紹就會一起配合這個方向，不會只換課名卻沿用無關介紹。

**這個檔案只整理資料清單，不會直接修改網站資料庫，也不會呼叫 AI 臨時生成內容。** 它沿用原有教師和課程的編號，不是每次執行就另外增加一批人。

### `demo_catalog.py`：大家共用的整理工具

位置：[scripts/demo_catalog.py](../scripts/demo_catalog.py)

這個檔案像是「共同使用的格式整理員」，讓編輯清單與放進資料庫的程式使用同一套規則。

例如：

- 把 `intro`、`beginner` 等程度名稱換成「入門」「初階」。
- 把課程介紹、教學安排、上課對象組成完整說明。
- 整理老師姓名、專長、簡介與教法，放到網站需要的位置。
- 協助確認資料庫裡的舊內容是否是程式認得的版本，避免蓋掉別人手動修改的內容。

它通常由其他程式使用，不需要單獨執行。

### `import_demo_data.py`：把清單放進網站資料庫

位置：[scripts/import_demo_data.py](../scripts/import_demo_data.py)

這是匯入假資料的主程式。它讀取準備好的教師與課程清單，先檢查，再依序建立網站需要的資料：

1. **教師使用者資料**：讓網站知道這個人是老師。
2. **教師介紹**：包含姓名、專長、簡介與教學方式。
3. **示範教師申請資料**：設為已通過，讓這批示範老師可以出現在產品流程裡；不代表真實資格審查。
4. **課程資料**：包含課名、程度、曲風、地區、費用、時段與介紹，並連到對應老師。

同一位老師可以有多門課，所以是 226 位教師對應 426 門課程。

程式記得每位教師與每門課原有的編號，重跑相同資料時會沿用既有資料，不會再多生一批。若要更新舊版介紹，可以使用更新選項；但如果有人手動改過、程式無法確認是否可以覆蓋，就會先停止，讓人檢查。

更新既有課程時，主要替換課名、程度、曲風與介紹，原有費用、時段、圖片、參考曲與師生關係會保留。

**這批教師沒有設定可供密碼登入的帳密。** 用途是展示與測試課程，不是提供 226 組登入帳號。

### `cloud_command.py`：帶著雲端設定執行匯入

位置：[scripts/cloud_command.py](../scripts/cloud_command.py)

這個檔案像是「選好目的地的入口」。它先讀取團隊的雲端設定，例如要連哪個資料庫，再把工作交給實際負責的程式。

使用它的 `seed` 指令時，最後執行的仍然是 `import_demo_data.py`。它不負責編教師名字，也不負責寫課程介紹。

**資料進本機還是 Supabase，取決於執行時的資料庫設定。** 在本機匯入一次，不會自動同步到雲端。

### `index_course_embeddings.py`：讓 AI 找課可以比較課程意思

位置：[scripts/index_course_embeddings.py](../scripts/index_course_embeddings.py)

教師與課程放進資料庫後，網站已經能顯示及搜尋課程。如果還要讓 AI 找課依使用者的意思排列課程，就需要另外執行這個檔案。

它會把已發布課程的標題、曲風與介紹交給 BGE-M3 模型，轉成電腦能比較的數字，存回資料庫。例如使用者說「想學電影配樂」，系統就能比較哪些課程的內容與這句話比較接近。

它不會建立教師或課程。課程內容改了之後，需要再執行，讓 AI 找課使用更新後的內容。

## 三、程式讀的資料放在哪裡？

這些 JSON 檔可以理解成「供程式讀取的資料清單」。

| 資料檔 | 裡面放什麼？ | 誰會使用？ |
| --- | --- | --- |
| `scripts/data/piano-curriculum.json` | 準備好的課程主題、課綱與學習方向。 | `build_demo_catalog.py` |
| `scripts/data/aicourse-demo.json` | 完整的 226 位教師與 426 門課程清單，包含哪門課屬於哪位老師。 | `build_demo_catalog.py`、`import_demo_data.py` |
| `scripts/data/aicourse-demo-versions.json` | 程式認得的歷史內容紀錄，協助判斷舊資料能不能更新。 | `import_demo_data.py` |

目前的內容是依事先準備的主題、文字與名字組合而成，並不是匯入時即時請 Ollama 想出 426 門課。主題規劃的背景可參考 [鋼琴課程目錄重編說明](piano-catalog-research.md)。

## 四、實際使用時，該執行哪個檔案？

| 想做的事 | 使用的檔案 |
| --- | --- |
| 重新編排教師名稱、專長與課程內容，產生更新後的清單。 | `build_demo_catalog.py` |
| 把現有清單放進本機資料庫。 | `import_demo_data.py` |
| 使用團隊的雲端設定，把清單放進測試用雲端資料庫。 | `cloud_command.py` 的 `seed` 指令，內部再執行 `import_demo_data.py`。 |
| 讓 AI 找課能使用新增或修改後的課程內容。 | `index_course_embeddings.py` |

例如，只是要把目前這批資料放到另一個測試環境，直接匯入現有清單即可，不必先重新編課程。

匯入程式預設會先試做並檢查，最後不保留新增或修改的資料。確認目標資料庫及結果後，加上 `--apply` 與正確的資料庫名稱，才會真正保存。完整雲端操作可參考 [既有重做與更新步驟](piano-catalog-research.md#重做與更新)；AI 找課的後續操作見 [資料庫與索引](shared-local-ai.md#資料庫與索引)。

## 五、不要和登入展示帳號搞混

`backend/services/demo_accounts.py` 是另一套用途：準備可以登入展示的老師、學生帳號，以及課程、對話、約課等教學情境。

本文說明的 `scripts/import_demo_data.py`，則是匯入大量教師與課程，讓課程列表、搜尋與 AI 找課有足夠資料可以測試。兩者各自服務不同的展示需求。
