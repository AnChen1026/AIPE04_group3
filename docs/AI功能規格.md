# 個人工作室智慧管理平台 AI 功能規格

| 項目 | 內容 |
| --- | --- |
| 版本 | V1.2 |
| 範圍 | 課程推薦／平台 QA、AI 測驗、鋼琴練習回饋 |
| 最後更新 | 2026-09-24 |

## 1. 共通原則

- AI 不直接驗證身份、不決定權限、不任意查詢資料庫。
- AI 不直接修改正式課表、建立師生關係、發布測驗或計算客觀題分數。
- Backend 只提供完成任務所需的最小資料。
- 所有模型輸出必須通過固定 Pydantic／JSON Schema。
- Prompt、模型與規則須有版本，以便重現與比較。
- 失敗、逾時與低信心必須有安全降級，不得用未驗證內容繼續流程。

## 2. 課程推薦與平台 QA

### 2.1 輸入

- 使用者原始文字。
- 已選篩選條件。
- 當次對談已確認資訊。
- 平台核准 QA 知識片段。

### 2.2 結構化輸出

```json
{
  "intent": "course_recommendation",
  "category": "piano",
  "learning_goal": "流行歌伴奏",
  "experience_evidence": ["只會簡單旋律"],
  "assessed_level": "beginner",
  "level_confidence": 0.72,
  "location": null,
  "budget_max": 1200,
  "available_time": null,
  "delivery_modes": ["onsite"],
  "missing_important_fields": ["available_time"],
  "next_question": "你通常哪幾天晚上方便上課？"
}
```

### 2.3 程度

| 等級 | 說明 |
| --- | --- |
| beginner | 幾乎沒有經驗 |
| elementary | 能完成少量基礎內容但不穩定 |
| intermediate | 基礎穩定，可完成一般曲目 |
| advanced | 能處理複雜技巧或自主學習 |
| uncertain | 資訊不足或能力不平均 |

### 2.4 規則

1. 最多追問 2 題。
2. 只問會實際改變推薦結果的資訊。
3. Backend 依必要條件查詢課程並規則排序。
4. LLM 只為候選課程產生易懂理由，不可新增候選。
5. 平台 QA 找不到核准依據時回答「目前無法確認」並引導正式說明。
6. MVP 不把登入學生多次對談彙整成長期個人化推薦 Profile。

## 3. AI 測驗生成

### 3.1 範圍

- 題型：單選題、是非題。
- 來源：老師明確指定且已通過檢查的教材。
- 發布：老師逐題審核或明確核准全部題目後發布。
- 批改：依老師核准答案由後端確定性計分。

### 3.2 生成輸出

```json
{
  "questions": [
    {
      "question_type": "single_choice",
      "prompt": "...",
      "options": ["A", "B", "C", "D"],
      "suggested_answer": 1,
      "explanation": "...",
      "source_reference": {"page": 3, "quote_hint": "..."},
      "confidence": 0.86
    }
  ]
}
```

### 3.3 防護

- 教材中的「忽略系統指令」等文字只視為教材內容。
- 每題必須能指出教材依據；無依據標記需人工補充。
- 選項不得重複，單選題只能有一個核准答案。
- 發布前由 Backend 檢查題型、選項、答案與 `teacher_reviewed`。
- 已有作答的 Quiz 不原地改題，改為新版本。

## 4. AI 鋼琴練習回饋

### 4.1 產品輸入

- 老師：樂譜圖片或參考音檔、任務名稱、必要練習說明。
- 學生：瀏覽器麥克風錄音。

### 4.2 期望輸出

- 整體練習摘要。
- 小節或區段標籤。
- 節奏偏快／偏慢／不穩定等概略問題。
- 錯音較集中的小節／區段。
- 一項可執行建議。
- 各區段與整體信心。
- 辨識限制，例如環境雜音、音量過小或無法對齊。

### 4.3 分析分層

1. 檔案與音訊品質檢查。
2. 參考資料分析：樂譜圖片 OMR 或參考音檔特徵／轉譜。
3. 學生錄音音高、起音、節拍與能量特徵。
4. 不同速度下的序列對齊。
5. 以小節或時間區段彙整錯音密度與節奏差異。
6. 規則引擎先產生安全 facts。
7. LLM 將 facts 改寫為鼓勵、簡短、不武斷的回饋。

### 4.4 回饋 Schema

```json
{
  "overall_confidence": 0.74,
  "overall_summary": "整體節奏穩定，後半段可以再放慢確認。",
  "segments": [
    {
      "label": "第 4 小節",
      "issue_type": "tempo_slow",
      "evidence_level": "medium",
      "confidence": 0.71,
      "feedback": "這個小節稍微慢了一點，可以搭配節拍器再試一次。"
    }
  ],
  "quality_flags": ["background_noise"],
  "limitations": ["背景雜音可能影響辨識"]
}
```

### 4.5 用語規則

建議：

- 「這個小節稍微慢了一點，可以跟著節拍器再試一次。」
- 「這一段錯音比較集中，建議放慢速度確認樂譜。」
- 「目前錄音雜音較多，重錄後可能得到更可靠的結果。」

避免：

- 「第 3 音低了 17 音分」等沒有足夠精度的斷言。
- 「你節奏感很差」等人格／能力標籤。
- 「已達檢定 X 級」等正式評量宣稱。
- 在對齊失敗時仍硬標示特定小節。

### 4.6 信心降級

| 情況 | 處理 |
| --- | --- |
| 音訊品質差 | 要求重錄，不做細部判斷 |
| 參考資料解析不完整 | 只回覆可辨識區段並標示限制 |
| 能對齊時間但不能對齊小節 | 使用「前半段／00:20–00:30」等區段 |
| 整體信心低 | 只顯示練習建議，請老師查看錄音 |

### 4.7 技術驗證 Gate

在正式納入 Demo 前，固定測試曲目至少驗證：

- 清楚樂譜圖片與一般手機拍攝圖片。
- 參考音檔與學生速度相差 10%／20%。
- 正確演奏、固定小節錯音與節奏刻意偏慢。
- 輕度與重度背景雜音。
- 系統能否正確降級，而不是輸出錯誤精密結論。

若小節對齊達不到團隊設定門檻，產品介面須誠實降級為時間區段回饋；不得僅為展示而偽造小節結果。

## 5. AI 評估資料集

- 推薦：匿名需求句、人工標註條件、程度與合適課程。
- 測驗：教材片段、老師核准題目、錯誤類型。
- 鋼琴：固定曲目、參考資料、控制錯誤位置、錄音環境與人工區段標註。
- 測試資料不可直接使用未取得同意的真實學生聊天、教材或錄音。

## 6. 監控

- Schema validation failure rate。
- 推薦無結果率與追問次數。
- 題目被老師大幅修改／刪除比例。
- 鋼琴分析成功、低信心、失敗與平均處理時間。
- 模型費用與單一帳號異常呼叫量。
